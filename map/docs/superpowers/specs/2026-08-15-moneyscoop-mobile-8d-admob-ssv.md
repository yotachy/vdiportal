# 머니스쿱 모바일 8d — AdMob 리워드 광고 + SSV

> 대상: `map/mobile/` + `map/wallet-*.php` · 설계일 2026-08-15
> 선행: 8b(서버 원장) · 8c(구글 로그인) · [`ANDROID-BUILD.md`](../../../mobile/docs/ANDROID-BUILD.md)
> 근거: `mobile/docs/design_handoff/SPEC-economy.md` §2 · §3 · §6

## 왜

**경제의 절반이 비어 있다.** 지갑은 쓰는 길(`full` 3 · `scan` 2)만 있고 버는 길이 체크인 하나뿐이다 —
하루 1개, 7일마다 +5. Full 리포트가 3개이므로 신규 사용자가 개설 지급 5개를 쓰고 나면 사실상 막힌다.
설계가 그 자리에 둔 것이 광고이고, 배선이 0이다.

이 페이즈는 **네이티브 SDK 를 처음 넣는다.** 지금까지는 웹 자산만 바꿔 빌드했으나 여기서는 Gradle
의존성·`AndroidManifest` 앱 ID·플러그인이 들어간다. 8d 가 안드로이드 빌드에 묶여 있던 이유이고,
그 빌드는 2026-08-15 에 처음 성공했다.

## 정하고 들어가는 것

| 결정 | 값 | 근거 |
|---|---|---|
| 지급 반영 | **잠깐 기다리기.** "적립하는 중…" + 폴링(2초 간격·10초) | `SPEC §2` 는 낙관적 반영을 적었지만, SSV 가 안 오면 잔량을 도로 내려야 하고 그건 "준 걸 뺏겼다"로 읽힌다. 8b 의 "클라이언트는 잔량을 계산하지 않는다"와도 이쪽이 일관된다 |
| 광고 위치 | **지갑 화면 상시 + 잔량 부족한 순간** | 지갑만 두면 그 화면을 안 여는 사용자는 광고가 있는 줄도 모른다. 부족한 순간만 두면 미리 모아두려는 경로가 없다 |
| UMP 재열람 | **지갑 화면 '광고 설정' 행** | 설정 화면이 없다. 광고가 사는 곳과 같은 화면이라 맥락이 맞고, 설정 화면을 새로 만드는 범위를 피한다. 대상 지역이 아니면 행 자체를 숨긴다 |
| AdMob 자격증명 | **테스트 유닛 ID 로 전 과정 개발.** 실 ID 는 설정 파일 하나로 교체 | 8c 의 `forge_google_oauth.json` 과 같은 무중단 스위치. 계정 개설은 사용자 몫이라 그것 때문에 구현이 멈추면 안 된다 |
| 일 상한 도달 | **줄을 숨기지 않고 문구를 바꾼다** | 사라지면 사용자는 앱이 고장난 줄 안다(온보딩 `auth-disabled` 에서 같은 판단을 했다) |

## 1. 지급 경로 — 클라이언트는 "봤다"고 말하지 않는다

`SPEC §2` 의 핵심은 광고 완료 이벤트를 신뢰하지 않는 것이다. 루트된 기기에서 웹뷰의 JS 를 불러
"다 봤다"를 만드는 것은 사소하고, 그것이 정확히 AdMob 의 남용 탐지가 보는 신호다.

```
앱                     구글                      우리 서버
 │  광고 요청 (custom_data = 계정 id, user_id = 계정 id)
 ├────────────────────▶│
 │  ← 광고 재생 · 완료 ─┤
 │                     │  SSV 콜백(서명됨) ────────▶│  ① 서명 검증
 │                     │                           │  ② transaction_id 중복 확인
 │                     │                           │  ③ 상한·쿨다운 확인 → 적립
 │  "적립하는 중…" 폴링 ─────────────────────────▶│
 │  ← 새 잔량 ──────────────────────────────────┤
```

**절대 `onAdDismissed` 에서 지급하지 않는다.** 지급은 오직 ③ 뿐이다.

### 서명 검증이 급소다

검증 없는 SSV 엔드포인트는 **공개 수도꼭지**다 — 누구나 그 URL 에 `reward_amount` 를 붙여 호출하면
잔량이 오른다. 인증이 없는 것이 정상인 엔드포인트라(구글이 부른다) 서명만이 유일한 방어선이다.

- 구글 공개키: `https://www.gstatic.com/admob/reward/verifier-keys.json`. `key_id` 로 고른다
- 서명 대상은 쿼리 문자열에서 **`&signature=` 앞까지**. 그 뒤(`signature`·`key_id`)는 제외
- ECDSA(SHA-256), base64url 서명
- 키는 파일로 캐시한다. **검증 실패 시 키를 새로 받아 한 번만 재시도** — 구글이 키를 교체하기 때문이며,
  무한 재시도로 만들면 서명 위조 시도가 곧 키 서버 DoS 가 된다
- `timestamp` 가 현재에서 **1시간 이상 벗어나면 거절**(재생 공격 완화)

### 중복과 상한

- `ad_grants` 테이블, `transaction_id` **UNIQUE**. 구글은 콜백을 재시도하므로 중복은 정상이며
  조용히 무시한다(200 을 돌려준다 — 아니면 구글이 계속 재시도한다)
- 상한은 전부 **서버 시각** 기준이고 **계정 단위**다(기기 단위가 아니다 — 8c 이후 기기 여럿이 한
  계정을 볼 수 있고, 기기 기준이면 기기를 늘려 상한을 곱할 수 있다): 일 8회 · 재시청 2분 쿨다운 ·
  지갑 상한 20(`W_CAP`). 기기 시계를 바꿔도 얻는 것이 없어야 한다
- **모르는 계정으로 온 콜백은 조용히 무시하고 200 을 돌려준다.** 404 를 주면 구글이 계속 재시도하고,
  응답으로 계정 존재 여부를 구별해 주면 공개 엔드포인트가 계정 열거 도구가 된다
- 지갑 상한에 걸리면 **적립을 잘라서 넣는다**(0 이 될 수도 있다). 이 경우도 `ad_grants` 에는 기록해
  일 상한을 소모한 것으로 친다 — 안 그러면 상한에 걸린 사용자가 광고를 무한히 보게 된다

## 2. 서버

`wallet-lib.php` · `wallet-api.php` 에 더하고, SSV 콜백은 **별도 파일**로 둔다.

**`wallet-ssv.php`(신규)** — 구글이 부르는 공개 GET 엔드포인트. `wallet-auth.php` 를 분리한 것과 같은
이유다: 인증 방식(서명 vs 베어러)도 응답 형식(빈 200 vs JSON)도 다르다. 한 파일에 넣으면
CORS 헤더와 베어러 검사가 뒤섞인다.

| op / 엔드포인트 | 동작 |
|---|---|
| `wallet-ssv.php` (GET) | 서명 검증 → 중복·상한 확인 → 적립. 항상 **빈 200** (본문에 아무것도 흘리지 않는다) |
| `adConfig` (op) | 광고 유닛 ID·상한·쿨다운을 앱에 준다. 설정 파일이 없으면 `{ok:false, reason:"ads-disabled"}` |
| `adState` (op) | 오늘 남은 횟수·다음 시청 가능 시각. 폴링이 아니라 화면 그릴 때 한 번 |

지급 폴링은 새 op 를 만들지 않는다 — 기존 `get` 을 그대로 쓴다. 잔량이 오르면 그것이 도착 신호다.

### 스키마 v4

프로덕션 SQLite **3.26.0** — `RETURNING`·`STRICT`·`ALTER TABLE ... DROP COLUMN` 불가.

```sql
create table if not exists ad_grants (
  transaction_id TEXT PRIMARY KEY, account_id TEXT NOT NULL, unit TEXT NOT NULL,
  amount INTEGER NOT NULL, granted INTEGER NOT NULL, created_at TEXT NOT NULL);
create index if not exists ix_ad_acct on ad_grants (account_id, created_at);
```

`transaction_id` 를 PK 로 두면 중복 삽입이 DB 층에서 막힌다 — 앱 층 검사만으로는 동시 재시도에서
둘 다 통과한다(8c 에서 같은 교훈을 얻었다). `amount` 는 구글이 말한 값, `granted` 는 상한을 적용해
실제로 넣은 값 — 둘이 다를 수 있고, 다른 이유를 나중에 설명할 수 있어야 한다.

적립은 8b 규율 그대로 — `BEGIN IMMEDIATE` + `busy_timeout`, 원장 `idem` 은 `ad:<transaction_id>`.

### `w_spend` 선행 수정

8c 최종 리뷰가 지목한 항목이며 **이 페이즈의 선행 조건**이다. `w_is_merged_away` 를 `w_checkin`·
`w_refund` 는 보는데 `w_spend` 는 안 본다. 지금은 병합된 계정 잔량이 0이라 우연히 안전하지만,
**광고 지급이 `w_checkin` 을 거치지 않고 적립하는 첫 경로**라 그 순간 죽은 지갑이 되살아난다.
`w_ad_grant` 도 같은 검사를 해야 한다.

## 3. 앱

### 네이티브

**`@capacitor-community/admob@8.1.0`** 을 쓴다. 설계 시점에 확인한 사실: 이 버전이 요구하는
`@capacitor/core ^8.0.0` 과 우리가 쓰는 `8.5.0` 이 맞고, 런타임 의존성이 그 하나뿐이다(나머지는
문서 생성 도구). 이 저장소의 **첫 네이티브 의존성**이므로 `package.json` 에 캐럿 없이 정확한 버전으로
박는다 — 자동 올림이 빌드를 흔드는 것이 이 자리에서 가장 비싼 사고다.

`AndroidManifest.xml` 에 AdMob 앱 ID 가 들어간다. **테스트 앱 ID 로 커밋하고**, 실 ID 는 배포 시
교체한다 — 실 ID 를 저장소에 넣으면 남이 우리 계정으로 광고를 띄울 수 있다.

`npm run cap:sync` 만으로는 부족하다. 플러그인이 추가되면 Gradle 의존성이 바뀌므로
`ANDROID-BUILD.md` 에 그 절차를 더한다.

### 화면

**지갑 화면** — 광고 두 줄(Quick 15초 +1 · Full 30초 +3), 그 아래 '광고 설정'(UMP 대상 지역만).
일 상한을 다 쓰면 두 줄이 *"오늘 광고는 다 봤습니다"* 로 바뀐다. 쿨다운 중이면 남은 시간을 보여준다.

**잔량 부족한 순간** — Full 리포트를 누르려는데 잔량이 모자라면 그 자리에서 광고를 권한다.
광고를 보고 잔량이 차면 **원래 하려던 분석으로 이어진다** — 지갑 화면으로 튕기지 않는다.

**광고 종료 후** — "적립하는 중…" + `get` 폴링(2초 간격, 10초까지). 도착하면 새 잔량,
안 오면 *"잠시 후 반영됩니다"*. **잔량이 줄어드는 순간을 만들지 않는다.**

`ads-disabled`(설정 파일 없음)면 광고 줄과 '광고 설정' 행을 **전부 숨긴다** — 8c 의 `auth-disabled`
와 같은 처리이며, 눌러도 아무 일 없는 버튼을 남기지 않는다.

### 고지

`SPEC §6`: *"Scoops have no cash value and cannot be transferred or refunded."* 지갑 화면에 상시 표기.
리워드 화폐에 요구되는 문구이고 스토어 심사가 본다.

## 4. 검증

| 검사 | 왜 |
|---|---|
| **서명이 틀린 SSV 콜백은 적립하지 않는다** | 이 페이즈에서 유일하게 돈을 만드는 문이다. 열려 있으면 잔량이 무한이 된다 |
| `signature` 뒤 파라미터를 서명 대상에 넣으면 검증이 깨진다 | 서명 범위를 정확히 잡았는지. 범위가 틀리면 정상 콜백이 전부 거절되거나(기능 정지) 전부 통과한다(수도꼭지) |
| 같은 `transaction_id` 두 번 → 한 번만 적립, 둘 다 200 | 구글은 재시도한다. 500 을 주면 영원히 재시도한다 |
| 동시 같은 `transaction_id` → 계정 잔량이 한 번만 오른다 | 앱 층 검사만으로는 경합에서 둘 다 통과한다 |
| 일 8회 초과 → 적립 없음, 그래도 200 | 상한이 서버 시각 기준인지 |
| 지갑 상한(20) 초과 → 잘라서 넣고 **일 상한은 소모** | 안 그러면 상한에 걸린 사용자가 무한히 광고를 본다 |
| 병합된 계정에는 적립하지 않는다 | 죽은 지갑이 광고로 되살아나면 8c 의 one-wallet 규율이 무너진다 |
| `timestamp` 가 1시간 밖이면 거절 | 재생 공격 |
| 설정 파일 없으면 광고 줄이 안 보인다 | 무중단 스위치 |
| **응답 본문에 아무것도 흘리지 않는다** | 공개·무인증 엔드포인트다. 경로·잔량·계정 존재 여부 전부 |

`map/tests/run.sh` 의 `wallet`·`wallet-dispatcher`·`concurrency` 에 붙는다.
**구글에 접속하지 않는다** — 공개키는 고정 픽스처로, 서명은 테스트 키쌍으로 만든다.

**기대값은 구현 상수가 아니라 밖에서 쓴다.**

## 5. 범위 밖

- **배너·전면 광고** — 리워드만. 다른 형식은 화면 설계 자체가 다르다
- **광고 수익 대시보드** — AdMob 콘솔이 이미 한다
- **iOS** — 안드로이드 단독 출시
- **릴리스 서명·스토어 등록** — 별도 작업. 8d 는 디버그 빌드에서 테스트 광고까지
- **`Custom` 티어**(5스쿱) — 엔진에 `pred.second` 생산자가 없다. 별도 엔진 과제
- **슬롯 과금 · 비답변 무과금** — 세밀한 기능 트랙
