> **순서를 앞당긴다.** 원래 페이즈 순서는 P1b(유료 경로) → P2 → P3 → P4 였다. 온보딩을 먼저 하는 이유는 사용자 판정("처음 접속하는 사용자 입장에서 부실하다")이 **첫인상 문제**이고, 첫인상이 나쁘면 뒤 페이즈가 아무리 좋아도 그 화면까지 사람이 오지 않기 때문이다. P1b 는 이 작업 뒤로 밀린다.

---

## 1. 왜 다시 짜는가

사용자가 콜드오픈 개선분을 포함한 현행 7단계를 보고 내린 판정:

> "처음 앱에 접속하는 사용자 입장에서 뭔가 많이 부실해. 첫 랜딩 화면을 포함해 7개 단계의 화면의 **스토리가 개연성이 부족**하고 **동작 또한 통일감이 없어.** … 7번째까지의 결과를 얻는 체험이라고 보기엔 **개연성/스토리/UX/직관적으로 너무 품질이 떨어져**"

구체 지적 다섯 (코드에서 전부 확인됨):

| # | 지적 | 코드 확인 |
|---|---|---|
| 1 | 1단계 차트에 **x축 기준(일봉/주봉)이 없다** | `screens/onboarding.js` step1 — 축 라벨은 날짜뿐, 주기 표기 없음 |
| 2 | 결과 화면에 **앱의 예측이 없다** — 실제 결과만 | `obGuessActual*` 이 실제 방향만 말한다. 엔진 판정은 별도 블록이라 "당신 vs 앱" 대비가 없음 |
| 3 | 2단계(성향)가 **왜 지금인지 없고 체험으로 이어지지 않는다** | `step2()` 는 라디오 4개뿐. 고른 값이 그 화면에서 아무것도 바꾸지 않음 |
| 4 | 3단계(동의)가 **갑자기 나온다** | `step3()` 앞뒤에 서사 연결이 없음 |
| 5 | 4단계가 **종목을 고르기만 해도 분석이 시작된 것처럼** 동작 · **오늘 값이 없고** 내일 값만 있으며 · **도구 5개가 어떻게 그 값을 만들었는지 데이터가 없다** | `canNext()` 가 `!!state.r1` — 결과 존재가 곧 진행 조건이라 명시적 실행 버튼이 없다 |

근본 원인은 하나다. **일곱 화면이 각자 존재하고 이야기의 축이 없다.** 설정 수집(성향·동의·종목)이 체험과 따로 놀아 "왜 지금 이걸 묻지?"가 반복된다.

## 2. 확정된 결정 (사용자, 2026-08-18)

| # | 결정 | 근거 |
|---|---|---|
| O1 | **이야기 축 = 한 종목을 끝까지 따라간다** | 예시 구간으로 시작해 같은 종목으로 끝까지. 설정은 **다음 장면이 필요로 할 때만** 묻는다 |
| O2 | **실력의 증거 = 근거의 투명성** | 32개 도구가 각각 무엇을 보고 무엇을 말했는지, **반대하는 도구까지** 보여준다. 거짓이 아니고 화면에서 바로 보이며 경쟁 앱과 가장 다른 점 |
| O3 | **동의는 미래를 예측하기 직전에만** | 과거 구간 해설은 교육이므로 동의 없이. "이제 진짜 예측을 보여드립니다 — 다만 약속이 아닙니다"로 이야기가 연결된다 |
| O4 | **3막 7단계**(A안) | 화면 수는 유지하되 내용이 두꺼워지고 각 단계가 앞 단계의 질문에 답한다 |
| O5 | **품질 기준은 "전문기업 다운"** — 시안은 상한이 아니라 하한 | 사용자 지시: "디자인 시안보다 더 좋게 해도 되" |

**O2 의 제약**: 이 엔진의 실측 방향 적중률은 **58.5%**, 자명 기준선(항상 상승)은 **60.96%** 다(상위 설계서 §9.1). **"잘 맞힌다"로 팔면 거짓말이 된다.** 그래서 증거를 적중률이 아니라 **근거의 투명성**에 둔다.

## 3. 3막 구조

```
1막 · 과거로 배운다 (동의 불필요)
  1) 예시 구간 · 도구 3개 힌트 · 찍기 → 당신 / 앱 / 실제 3열
  2) 같은 구간에 32개 전부 → 동의·반대·무판정
2막 · 내 기준을 넣는다
  3) 성향 → 같은 구간 판정이 즉시 갱신
3막 · 내 종목으로 (동의 필요)
  4) 위험 고지 · 동의
  5) 종목 선택 → [분석 시작]
  6) 실제 분석 — 오늘 → 내일 → 1주 → 1개월 + 근거
  7) 가격표 · 스쿱 10개
```

각 단계는 **앞 단계가 남긴 질문에 답한다**. 그것이 개연성이다.

## 4. 단계별 설계

### 4.1 — 1단계: 예시 구간, 찍기, 3열 비교

현행 콜드오픈(`0fcc39d`)을 **확장**한다. 버리지 않는다.

**유지**: 실데이터 구간(전형 밴드에서 선별, 이동폭 49.7 퍼센타일) · 이동평균·볼린저·거래량 작도 + 도구별 한 줄 힌트 · 엔진 런타임 판독 · "설명을 위해 고른 예시 구간입니다"

**더한다**:
- **주기·기간 표기** — 차트 상단에 `일봉 · 2005.05 ~ 2006.04` 고정. 지적 1
- **3열 비교** — 찍은 뒤 `당신 / 앱 / 실제` 를 나란히. 지적 2
  - 앱 열에는 판정과 **확신**이 아니라 **판정과 근거 요약**이 들어간다(확신 퍼센트는 이 단계에서 쓰지 않는다 — 5개 도구로는 0·20·40·60·80·100 뿐이라 확률로 오독된다, 상위 설계서 §3.2 와 같은 이유)
  - **앱이 틀린 표본이면 틀렸다고 쓴다.** 현재 표본은 맞은 케이스이므로 그 사실이 "항상 맞는다"로 읽히지 않게 §6 의 표기를 함께 둔다
- **다음을 벌어들이는 한 줄** — "앱은 도구 **5개**만 보고 이렇게 말했습니다."

### 4.2 — 2단계: 같은 구간, 32개 전부 (O2 의 증거)

**이 화면이 이 온보딩의 핵심이다.** 1단계가 남긴 질문("5개만 봤다면 나머지는?")에 답한다.

- **같은 구간·같은 시점**에 32개 도구를 전부 실행해 펼친다
- 세 통으로 나눈다: **동의 / 반대 / 무판정**. 합이 32와 맞아야 한다
- **반대하는 도구를 접지 않는다** — 이것이 O2 의 실체다. "다른 곳은 결론만 주지만 우리는 계산 과정을 연다"
- 각 도구는 **이름(영어 유지) · 무엇을 봤는지 · 실측 수치**. 수치가 없으면 검증 불가능한 주장이 된다
- 5개일 때의 판정과 32개일 때의 판정을 **나란히** 둔다. 달라졌다면 그 사실이, 같다면 "더 많은 도구가 같은 결론을 지지했다"가 메시지
- 32줄을 한 번에 쏟지 않는다 — 동의/반대 대표 몇 줄을 먼저, 나머지는 펼치기

> **비용**: 32도구 실행은 실측 **360봉에서 약 40ms**(P1a Task 4 측정, 기본 5도구는 2.4ms). 예시 구간은 240봉이라 그보다 싸다. 이 화면에서 한 번 도는 것은 문제가 없다 — P1a 에서 제거한 것은 "무료 리포트를 **열 때마다** 32도구를 돌던 것"이지 32도구 실행 자체가 아니다.

**다음을 벌어들이는 한 줄** — "도구마다 중요도가 다릅니다. 무엇을 중시하시나요?"

### 4.3 — 3단계: 성향 (지적 3)

- 4종(단기 모멘텀 / 추세 추종 / 평균 회귀 / 변동성 우선) 중 **1개 필수**
- **고르는 즉시 같은 구간의 판정·근거 구성이 갱신된다.** 가중치는 `ind-tiers.js` 의 `PRESETS`(출처: PC `forge-ui.js` `_PRESET_DEF`)
- **다른 성향을 눌러 되돌려볼 수 있다** — 조작이 결과를 바꾸는 것을 직접 겪는 것이 이 단계의 목적
- 판정이 성향에 따라 **안 바뀔 수도 있다.** 그때는 "당신 기준으로도 같은 결론입니다"가 정직한 문구다 — 억지로 바뀌는 척하지 않는다

**다음을 벌어들이는 한 줄** — "여기까지는 **과거**였습니다."

### 4.4 — 4단계: 위험 고지 · 동의 (O3)

- 1막·2막이 과거였음을 명시하고, **지금부터 미래를 말한다**는 전환으로 연다
- 무엇을 하지 **않는지** 명시: 매수·매도 권유가 아니다 · 수익을 약속하지 않는다 · 손실 책임은 사용자에게 있다
- 체크박스 1개 필수. 동의 시각·약관 버전을 `ms_consent` 에 기록(기존 키 유지)

### 4.5 — 5단계: 종목 선택 (지적 5-a)

- 칩 그리드(12종) + 직접 입력. **1개**면 충분하다
- **선택과 실행을 분리한다.** 고르면 선택 표시만 바뀌고, 하단 **[분석 시작]** 버튼이 활성화된다. 진행 조건은 `state.r1` 같은 부수 효과가 아니라 **버튼 클릭**이다
- 종목을 못 찾거나 봉이 부족하면 **다음 행동**을 준다(다른 종목 고르기) — 막다른 골목 금지

### 4.6 — 6단계: 실제 분석 (지적 5-b, 5-c)

- **진행 중계** — `analyzeX` 한 번 = 한 칸. 타이머 흉내 금지. 캐시로 빨리 끝나면 빨리 보여준다
- 결과 순서: **오늘 종가(기준 시각 포함) → 내일 → 1주 → 1개월**. 각 지평은 중심값 ± 오차
- **그 값을 만든 근거**를 함께 — 2단계에서 배운 형식 그대로(동의/반대). 배운 읽기를 자기 종목에 적용하는 장면이다
- 세 지평이 **엇갈리면 엇갈린다고 쓴다**("단기는 위, 한 달은 아래") — 셋이 다 맞는 것만 보여주면 거짓이다
- 이것은 **실제 예측**이므로 "약속이 아님"을 결과 옆에 둔다

### 4.7 — 7단계: 완료 · 가격표 · 스쿱 10개

- **방금 받은 것**을 먼저 요약한다(도구 32개 · 지평 3개 · 근거 전부)
- 그다음 가격표. **순서가 핵심이다** — 값을 먼저 겪은 사람에게만 "3스쿱"이 비싼지 싼지 판단 근거가 생긴다
- 스쿱 10개 지급. 마크가 빈 원에서 차오르는 효과(시안 규약)
- **온보딩의 32도구 체험이 "앞으로도 무료"로 읽히지 않게** 가격표에서 분명히 한다

## 5. "전문기업 다운 품질"의 검사 가능한 정의 (O5)

말로 두면 안 지켜진다. **다섯 규칙을 관문으로 만든다.**

| # | 규칙 | 검사 방법 |
|---|---|---|
| Q1 | **모든 수치에 기준이 붙는다** — 값만 있는 숫자 금지(`32.10` ✗ / `오늘 종가 32.10 · 2006.04.25` ○) | 수치를 담는 DOM 노드가 단위·시점 노드와 **같은 그룹 안에** 있는지 구조로 검사 |
| Q2 | **모든 화면이 자기 위치를 안다** — 진행 표시 + 단계 제목 | 각 단계 렌더 결과에 진행 표시와 제목 노드가 존재 |
| Q3 | **로딩은 실제 진행** — 타이머 흉내 금지 | 진행 갱신이 엔진 이벤트에 묶였는지(고정 `setTimeout` 증가 금지) |
| Q4 | **되돌아갈 수 있다** — 1~3단계 자유 왕복, 4단계 이후 전진만 | 뒤로 이동 가능 여부를 단계별로 단언 |
| Q5 | **끝맺지 않은 문장 금지** — 값만 던지고 해석 없는 블록을 두지 않는다 | 수치 블록마다 해석 텍스트 노드가 동반하는지 구조로 검사 |

Q1·Q5 는 정규식이 아니라 **DOM 구조**로 검사한다 — 문구를 바꿔도 규칙이 살아 있어야 한다.

## 6. 무엇을 주장하지 않는가

상위 설계서 §9.3 을 이 화면에 적용한 것:

- 1·2·3단계는 **과거 구간**이고 "설명을 위해 고른 예시"임을 계속 표기한다. 선별 규칙(전형 밴드)과 그 회귀 시험은 이미 있다(`test/onboarding-sample.test.mjs`)
- **적중률을 온보딩에서 주장하지 않는다.** 부득이 언급하면 **자명 기준선(60.96%) 병기 + 범위 주석**(엔진 전체 측정값이지 이 종목이 아님)이 필수
- 1단계에서 **확신 퍼센트를 쓰지 않는다**(5개 도구는 여섯 값뿐이라 확률로 오독된다)
- 6단계는 실제 예측이므로 **약속이 아님**을 결과 옆에
- **온보딩 32도구 체험 ≠ 상시 무료**

## 8. 검증

- **단계별 실제 조립 시험** — 가짜 DOM 문자열 검사가 아니라 vm + 실제 모듈 로드(이 저장소의 `report-basic.test.mjs`·`shell-backbutton-e2e.test.mjs` 방식)
- **브라우저 관문에 7단계 전부** — 각 화면을 실제로 클릭해 넘어가며 스크린샷을 남긴다. 조건부 `if` 안에 갇혀 조용히 건너뛰는 단언 금지(이 저장소가 다섯 번 데인 패턴)
- **§5 다섯 규칙을 각각 관문 단언으로**
- **지적 다섯 가지를 회귀 시험으로 고정** — x축 표기 부재·앱 예측 병기 누락·성향 미배선·클릭이 곧 실행·오늘값 부재가 되돌아오면 빨개진다

## 9. 범위 밖

- 온보딩 **재실행 경로**(지갑 › 처음 안내 다시 보기)는 이미 있다 — 손대지 않는다
- 영어 UI(P5) · 폴드 2단(P5) · 실 AdMob 연결
- 심화·전문 티어의 잠금 해제는 **P1b** 소관이다. 온보딩의 32도구 체험은 그 잠금과 **무관하게** 동작해야 한다(체험은 과금 경로를 안 탄다)

## 10. 열린 항목

- **2단계에 32줄을 어떻게 접을 것인가** — 대표 몇 줄 + 펼치기로 정했으나, 몇 줄을 먼저 보일지는 구현 중 실물로 판단한다(첫 사용자에게 과하지 않게)
- **성향이 판정을 안 바꾸는 표본일 때** — 정직한 문구로 처리하기로 했으나, 현재 표본에서 4종 성향이 실제로 결과를 가르는지 **착수 시 측정**해야 한다. 안 갈린다면 표본을 다시 고르는 것이 옳은지(선별 기준에 "성향 민감도"를 더할지) 그때 판정한다
