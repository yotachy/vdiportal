# 머니스쿱 모바일 P1 — 디자인 기반 + 기존 화면 재스킨

**작성** 2026-08-16 · **시안** `map/mobile/docs/design_handoff/` (2026-08-16 번들) ·
**인벤토리** `map/mobile/docs/DESIGN-INVENTORY.md`

---

## 0. 이 문서의 자리

머니스쿱 모바일 **전면 개편 5페이즈 중 첫 번째**다. 전체 분해는 아래와 같고, 각 페이즈는 그 자체로
출시 가능하게 잘랐다 — 순수 리팩터로 끝나는 페이즈는 만들지 않았다.

| | 페이즈 | 담기는 것 |
|---|---|---|
| **P1** | **디자인 기반 + 기존 화면** | **본 문서** |
| P2 | 3티어 격차 | 차트 레이어 티어별 토글 · 정보 블록 3/8/9 · 전문분석 신설 · 판독문 32 · 단계적 공개 연출 · 막힘 7종 |
| P3 | 예측 결과 루프 | 서버 예측 기록(engineVersion 도장) · 다음날 판정 · 결과 카드 · 내 기록(n≥20) · 알림 · 재열람 |
| P4 | 광고 진입점 6곳 | 세션당 2회 상한 · 빗나간 날 금지 |
| P5 | 반응형 다단 + 영어 | 폴드 2단(680) · 태블릿 3단(1200) · 영어 UI 얹기 |

의존 관계상 이 순서가 강제된다. P4 의 진입점 4·5·6 은 P3 의 결과·스캔이 있어야 존재하고,
P2 의 티어 격차가 없으면 P4 가 팔 것이 없다. 영어는 시안 지시대로 한글 완성 뒤에 얹는다.

## 1. 목표

앱 전체를 새 디자인 언어로 갈아입히고 **한국어 앱으로 전환**한다. 기능은 늘리지 않는다 —
지금 동작하는 것이 새 옷을 입고 한국어로 말하게 하는 것까지가 P1 이다.

**성공 기준**

1. 앱의 모든 화면이 시안의 토큰·타이포 위계를 따른다.
2. 사용자가 보는 모든 문자열이 한국어다(지표명 제외 — 아래 §4).
3. 기기·안드로이드 버전이 달라도 글자가 같은 폭·같은 무게로 앉는다.
4. 기존에 동작하던 상태 처리가 하나도 사라지지 않는다.

**명시적 비목표**

- 새 화면·새 기능 없음. 전문분석은 잠금 표시만 하고 열지 않는다(P2).
- 예측 결과 카드 없음(P3). 영어 전환 없음(P5).
- 차트 내부 표현 변경 없음 — `draw-layers.js`·`draw-panels.js`·`chart-legend.js` 는 손대지 않는다.

## 2. 서체 — 시안의 지정을 그대로 쓸 수 없다

### 2.1 왜

시안 목업은 전부 `font-family:'Plus Jakarta Sans'` 를 선언하는데 **이 서체에는 한글이 없다.**
목업의 문장이 전부 한국어이므로, 디자이너가 화면에서 본 한글은 시스템 폰트로 폴백된 것이다.
지정한 서체와 실제로 본 화면이 달랐다.

우리 쪽도 같은 종류의 착각이 있었다. `style.css:18` 이 `font-family:Pretendard, …` 를 선언하지만
**저장소에 폰트 파일도 `@font-face` 도 없다.** 지금 앱은 안드로이드 시스템 폰트로 그려지고 있다.

### 2.2 결정 — Pretendard Variable 을 번들한다 (사용자 결정, 2026-08-16)

- **파일 1개**: `PretendardVariable.woff2` (OFL, **2.06MB 실측** — v1.3.9) → `www/fonts/` 에 두고 `@font-face` 로
  `font-weight:100 900` 선언. 시안이 요구하는 400·500·700·800 을 한 파일이 전부 덮는다.
  무게별 파일 4개를 받는 것보다 작고, 무게가 빠져 가짜 볼드(synthetic bold)로 그려지는 사고가 없다.
- **CDN 금지.** Capacitor 앱은 `https://localhost/` 에서 서빙되고 네트워크를 보장할 수 없다.
  반드시 번들한다. 이는 `map.html`(Pretendard CDN)과 다른 선택이며, 앱이라 다르다.
- **APK 영향**: 12.0MB → 약 14MB. 릴리스 빌드의 리소스 축소 과제와 함께 다시 볼 것.
  더 줄여야 하면 같은 저장소의 `PretendardVariable.subset.woff2`(KS X 1001 상용 한글)로 내릴 수
  있으나, 범위 밖 글자가 시스템 폰트로 폴백된다 — 크기가 실제 문제가 됐을 때만 바꾼다.
- **숫자 서체**: 시안은 수치에 Space Grotesk 를 지정하지만 **채택하지 않는다.** 숫자는 한글 바로
  옆에 상시 붙어 나오고(가격·스쿱 수·퍼센트), 라틴 서체를 섞으면 그 줄만 이질적으로 뜬다.
  Pretendard 의 `font-variant-numeric:tabular-nums` 로 자릿수를 고정하고, 시안이 지정한
  **크기·굵기·자간은 그대로 따른다**. 이는 판단이며 되돌리기 쉽다 — Space Grotesk 라틴 서브셋은
  약 25KB 라 나중에 얹을 수 있다.
- `.wl-price`·`.wl-chg` 의 `ui-monospace,Menlo,monospace` 는 제거하고 위 규칙으로 흡수한다.

### 2.3 타이포 위계

기존 `.rp-*` 는 4px 폭 안에 8단계(11·11.5·12·12.5·13·13.5·14·15)가 뒤섞여 위계가 무너져 있다.
아래 8역할로 정리하고, 새 크기를 임의로 추가하지 않는다.

| 역할 | 크기 / 굵기 | letter-spacing |
|---|---|---|
| 판정 헤드라인 | 40~44 / 800 | −0.05em |
| 화면 제목 | 22~27 / 800 | −0.04em |
| 섹션 제목 | 17~20 / 800 | −0.03em |
| 큰 수치 | 24~30 / 700 | −0.045em |
| 본문 | 13.5 / 400~500 | — |
| 보조 | 12 / 400 | — |
| 캡션 | 11.5 / 400 | — |
| 오버라인 | 11 / 700 | 0.05em |

## 3. 토큰

`:root` 는 시안이 우리 값에서 그려졌으므로 **색값 자체는 거의 그대로 간다**. 이번에 정리할 것만 적는다.

### 3.1 티어 3색 역할 고정

| 티어 | 토큰 | 값 |
|---|---|---|
| 기본분석 | `--steel` | `#8892a6` |
| 심화분석 | `--gold` | `#e8b463` |
| 전문분석 | `--platinum` | `#b9c4dc` |

골드는 **화폐·심화분석·예측선**에만 쓴다. 티어 색을 다른 용도로 빌려 쓰지 않는다.

### 3.2 `--pred2` 분리 — 이름이 두 가지 일을 하고 있다

개편은 보라 `#b892f5` 를 **행동색**(버튼·링크·강조 CTA)으로 쓴다. 그런데 이 토큰의 원래 소비자는
`chart-draw.js:123` 의 **2차 예측선**이다. 한 토큰이 두 역할을 지면 나중에 한쪽을 조정할 때 다른 쪽이
말없이 따라 움직인다.

- `--action:#b892f5` — **신설.** UI 행동색. 시안이 요구하는 그 보라다.
- `--pred2:#b892f5` — **값 그대로 유지.** 다만 주석으로 **차트 전용**임을 못박는다.

즉 **지금 두 색을 다르게 만들지 않는다.** 오늘은 같은 값이고 화면도 그대로다 — 바뀌는 것은
"버튼 색을 조정하면 차트 예측선이 따라 움직인다"는 연결이 끊긴다는 것뿐이다. 차트 색은 1차
예측선(골드)·3차 반대선과 나란히 놓고 봐야 정할 수 있으므로, 실제로 갈라야 할 필요가 생기면
그때 차트 위에서 정한다. 지면에서 미리 고르지 않는다.

### 3.3 금지 규칙 (코드 주석으로 남긴다)

- **`--neutral`(`#4a5368`)을 텍스트에 쓰지 않는다.** 대비 2.4:1. 점·채움 전용.
- **항목 좌측 세로 컬러 라인 금지.** 선택·활성은 배경색·텍스트색·체크·아웃라인으로만.
  (프로젝트 전역 규칙 — `no-left-accent-line`)
- **엘리베이션 그림자 없음.** `box-shadow` 는 선택 링과 지갑 점 inset 에만.

## 4. 문자열 — 한국어 전환

`www/strings.js` 가 UI 문자열 단일 출처다. 이 구조는 유지하고 값만 한국어로 바꾼다.

### 4.1 규칙

- **지표명은 영어 유지** — `IND` 맵 전체(`Moving average`·`RSI`·`Ichimoku` …). 기존 명시 규칙이다.
- 보간이 필요한 곳은 기존 관례를 따른다 — `{n}` 치환(`wMergeDiscarded`·`adQuick` 선례).
  새 보간 기계를 만들지 않는다.
- 문자열이 `strings.js` 밖으로 새지 않는다. 테스트가 이를 지킨다(§8).

### 4.2 함께 고치는 기존 결함 두 개

**① 티어명이 두 이름으로 갈려 있다 (기존 버그)**

| 키 | 현재 값 | 쓰이는 곳 |
|---|---|---|
| `tsFull` · `rpTierFull` | `Full` / `FULL` | 단계 선택 시트 · 리포트 |
| `walDeep` · `obCostFull` | `Deep analysis` | 지갑 · 온보딩 |

같은 단계다. 3단계 체계에서 "Full" 위에 전문분석이 오면 말이 되지 않으므로 **심화분석**으로 통일한다.
영어 키를 남길 때도 `Deep` 을 쓴다.

**② 지갑의 로그인 안내가 우리 코드와 어긋난다**

시안 10b 는 *"로그인이 아직 준비되지 않아, 앱을 지우면 스쿱도 사라집니다"* 라고 쓴다. 그러나 구글
로그인은 **8c 에서 이미 구현됐고 `forge_google_oauth.json` 업로드만 남았다.** 활성화되는 순간 이
문구는 거짓이 된다.

→ 로그인 상태로 갈라 쓴다: 미로그인이면 "이 기기에만 저장됩니다 · 로그인하면 계정에 남습니다",
로그인 상태면 계정 표시. 로그인 기능이 서버에서 아직 꺼져 있으면 시안 문구를 그대로 쓴다.
**화면이 서버 상태를 보고 말하게 하고, 문구에 사실을 박아두지 않는다.**

## 5. 아이콘 · 스플래시

시안이 `assets/` 에 **21장을 실물로 생성**했고 폴더 구조가 `android/app/src/main/res/` 와 그대로
대응한다.

| 항목 | 개수 | 크기 |
|---|---|---|
| `mipmap-*/ic_launcher_foreground.png` | 5 | 108 · 162 · 216 · 324 · 432 (투명) |
| `mipmap-*/ic_launcher.png` | 5 | 48 · 72 · 96 · 144 · 192 |
| `drawable-port-*/splash.png` | 5 | 320×480 ~ 1280×1920 |
| `drawable-land-*/splash.png` | 5 | 480×320 ~ 1920×1280 |
| `drawable/splash.png` | 1 | 480×320 |

- **적응형 아이콘 배경을 `#FFFFFF` → `#0a0d12` 로 바꾼다.** 다크 단독 앱인데 아이콘만 하얗게
  번쩍이던 것을 고치는 것이다. `res/values/ic_launcher_background.xml` 을 함께 고쳐야 한다.
- 48px 아이콘은 채움 42% 를 버리고 **꽉 찬 원**이다 — 부분 채움이 그 크기에서 얼룩으로 보이기 때문.
  앱 내 마크와 일부러 다른 유일한 지점이므로 "왜 다르지"로 되돌리지 말 것.
- 스플래시에 워드마크가 없다(0.4초 뒤 사라지는 화면의 글자는 읽히지 않는다).
- **헤더 마크**: `.wl-brand-mark` 는 22px 컨테이너만 있고 내용이 비어 있다. 스쿱 마크(채움 42%)를
  인라인 SVG 로 넣는다. 마크 벡터는 시안 번들의 `support.js` 에서 확인한다.

## 6. 화면 4종

각 화면의 구성·문구는 `DESIGN-INVENTORY.md` §1 의 해당 항목이 단일 출처다. 여기서는 **경계와
판단이 필요한 지점만** 적는다.

### 6.1 워치리스트 (14a)

- 헤더(워드마크 + 스쿱 필) → **"오늘" 섹션** + 스캔 버튼 → 종목 행 → `＋ 종목 추가` → 하단 탭.
- **상단의 "어제 본 예측 3건" 결과 카드는 P3 다.** 예측 기록 서버가 있어야 존재한다.
  P1 은 그 자리를 비워두는 것이 아니라 **"오늘" 섹션이 최상단**인 화면을 그린다 — 빈 껍데기를
  남기면 로딩 실패로 읽힌다.
- 읽음 상태 3종: 안 읽음(바이올렛 채움) / 읽음(빈 링) / 오래됨(회색). **확신 배지는 넣지 않는다**
  (목록에서 판정이 새면 리포트를 열 이유가 사라진다).
- 시안에 없는 상태 4종(비어있음·검색결과없음·스캔중·스캔실패)은 **기존 구현의 처리를 새 디자인으로
  옮긴다.** 시안에 없다는 이유로 동작하던 것을 지우지 않는다.

### 6.2 지갑 (10b)

- 잔량 카드 → **"버는 곳"**(출석 + "하나 더 받기"가 **같은 덩어리**) → "쓰는 곳" → "계정 · 설정".
- "하나 더 받기"가 출석과 시각적으로 이어붙는 것이 시안의 의도다. 별도 카드로 떼지 말 것.
- 광고 행은 8d 구현이 이미 있다 — 다시 만들지 말고 스타일만 새 디자인으로.
  `+{n}` 은 `adConfig()` 의 `reward` 에서 온다(리터럴 금지, 이미 그렇게 되어 있다).
- **언어 세그는 P5**. 이번에는 자리를 만들지 않는다.
- 엔진 버전 줄(`walEngine`)은 이번 라운드에 이미 들어갔다 — 새 디자인의 고지문 아래에 유지.
- 지갑 못 읽음 / 병합됨 / 상한 초과 상태는 기존 처리를 유지한다(8c·8d 에서 각각 문구가 확정됐다).

### 6.3 종목 추가 시트 (12a)

- **칩 그리드가 검색창보다 위**다 — 초심자는 티커를 모른다. 순서를 뒤집지 말 것.
- 이미 담은 종목은 목록에서 **지우지 않고 자물쇠로 표시**한다(사라지면 "왜 없지"가 된다).
- 자물쇠 아이콘은 14×14 단일 규격으로 **잠긴 지표·종목·티어 전부**에 같은 것을 쓴다.

### 6.4 단계 선택 시트 (6b)

- 제목은 "얼마나 정밀하게?".
- **전문분석 행은 잠금 표시**로 둔다(자물쇠 + 준비 중). P2 가 연다.
  현재 `tsSoon`("Coming soon")이 하던 일을 새 디자인의 잠금 표현으로 옮기는 것이다.

| `www/ui.js` | 공용 요소(시트·칩·자물쇠 아이콘) |
| `android/app/src/main/res/**` | 아이콘 21장 · 적응형 배경색 |

`style.css` 가 이미 크다. 화면별 스타일이 계속 붙을 것이므로, P1 에서 **토큰·타이포·공용 요소**와
**화면별 규칙**을 파일 안에서 명확히 구획하고, P2 에서 리포트 화면이 들어올 때 분할을 재검토한다.
지금 쪼개는 것은 이르다(어디서 갈릴지 P2 가 알려준다).

## 8. 테스트

기존 관문 `map/tests/run.sh` 에 붙는다. 모바일 스위트는 DOM 없이 도는 노드 테스트다.

**반드시 잡아야 하는 것**

1. **문자열 누출** — 화면 코드에 한글/영문 리터럴이 박히지 않았는지. `strings.js` 밖의 사용자 가시
   문자열은 실패다. (기존 테스트 확장)
2. **티어명 일관성** — `tsFull`·`rpTierFull`·`walDeep`·`obCostFull` 이 **같은 단어**를 쓰는지.
   이 테스트가 없었기 때문에 두 이름이 갈렸다.
3. **폰트 번들 존재** — `@font-face` 가 가리키는 파일이 실제로 `www/fonts/` 에 있고, `cap:sync`
   후 `android/app/src/main/assets/public/fonts/` 에도 있는지. **없어도 화면은 그려지므로**
   (시스템 폰트로 조용히 폴백) 사람 눈으로는 안 잡힌다 — 지금 Pretendard 가 정확히 그렇게 빠져
   있었다.
4. **토큰 사용** — 화면 CSS 에 하드코딩 헥스가 없는지(`var(--…)` 만).
5. **금지 규칙** — 좌측 accent bar(`border-left`·`box-shadow:inset Npx 0`)가 없는지.
6. **기존 상태 처리 보존** — 워치리스트·지갑의 실패/빈 상태가 재스킨 후에도 같은 조건에서 같은
   메시지를 내는지. 마크업을 다시 쓰는 작업이라 여기가 가장 잘 깨진다.

**시각 확인**: 헤드리스 크로미움 스크린샷(`headless-verify-wsl` 절차)으로 4화면을 폰·폴드 폭에서
찍어 시안과 나란히 본다. 단, 헤드리스는 실기기와 다르다 — 상태바 인셋 문제가 브라우저에서 안 보이고
첫 설치에서 드러난 전례가 있다(2026-08-15). **APK 로 실기기 확인까지가 완료 조건이다.**

## 10. 나중 페이즈로 넘기는 미결정

P1 을 막지는 않지만 잊으면 안 되는 것들이다.

- **리포트 레이아웃 택일(P2)** — 심화분석 결과 화면이 두 벌 완전 명세로 그려져 있다.
  판정을 먼저 놓는 18b 와 평이한 문장을 먼저 놓는 19b(최신). 하나를 골라야 한다.
- **투자성향 프리셋(P2~P4)** — 시안은 성향이 전문분석 가중치 기본값의 근거라 하는데, 포지의
  프리셋 9종은 *가중치*가 아니라 *표시할 지표 집합*이다. 다만 시안의 성향 4종
  (추세 추종·단기 모멘텀·평균 회귀·변동성 우선)이 **위험성향이 아니라 매매 스타일**이라,
  포지의 "추세 중심·모멘텀 중심·역추세·반전·돌파·변동성"과 거의 그대로 대응한다.
  지표 집합 → 가중치 변환(포함된 지표를 올리고 나머지는 1.0)만 정하면 지어낼 것이 없다.
  그 배율은 백테스트로 검증한다.
- **온보딩 진행바 칸 수** — 시안 목업은 6칸인데 정본 온보딩은 7단계다(위험 고지가 미작도라 프레임에
  반영되지 않았다). **7칸으로 구현한다.**
- **티어별 적중률 실측(P2) — 측정 완료. 결과가 시안의 전제를 뒤집는다.**
  `backtest/tier-backtest.js` 로 엔진 1.11.0 · 87종 · 각 31,971건을 쟀다(`backtest/tier-report.json`).

  | | 기본 (5종) | 심화 (32종) | 차이 |
  |---|---|---|---|
  | 방향 적중 | 58.18% | 58.54% | **+0.36%p** |
  | 콘 커버리지 | 73.8% | 77.1% | +3.3%p |
  | 확률 오차(ECE) | 1.05%p | 0.27%p | 4배 정직 |
  | 가격 오차(MAE) | 17.6% | 17.0% | −0.6%p |

  방향은 시안이 샘플로 적어둔 "2%p 만 오릅니다"보다 **다섯 배 작다.** 국면을 나누면 더 분명하다 —
  강세장 +0.45%p · **하락장 +0.03%p · 횡보장 +0.02%p.** 사용자가 도움이 가장 필요한 두 국면에서
  32종은 5종 대비 아무것도 사지 못한다.

  그러나 같은 측정이 심화가 파는 것을 알려준다: 확률 오차가 네 배 정직해지고 80% 콘의 실제 커버가
  라벨에 가까워진다. **심화분석은 "더 맞힌다"가 아니라 "더 정직하게 말한다".** P2 의 문구는 이
  사실 위에 쓴다 — 숫자를 고르지 않는다.

  두 티어 모두 **"항상 오른다"(61.0%)를 넘지 못한다.** 화면이 적중률만 보이면 사용자는 그것을
  "동전보다 낫다"로 읽는데, 이 자산·이 기간의 기준선은 50%가 아니라 61% 다. 적중률을 표시한다면
  **베이스라인을 옆에 함께** 적어야 한다.

  **전문분석은 재지 않았고 재서도 안 된다** — 사용자마다 가중치가 달라 하나의 적중률로 환원되지
  않는다. 화면에 전문분석 전용 적중률 숫자를 걸면 그것은 측정한 적 없는 값이다.
