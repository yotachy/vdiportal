# 드로잉 도구 2차 — 조작 개선 · 도구 확장 · 시각 고급화

- 날짜: 2026-08-06
- 대상: `forge-tools.js` · `forge-app.js`(커서·키) · `forge.css`(팝오버·스와치) · `forge.html`(도구 2종 버튼)
- 선행: `2026-08-06-chart-drawing-tools-design.md`(1차 — 앵커 모델·4도구·마그넷)
- 상태: 설계 승인됨

## 1. 배경

1차 배포 후 사용자 피드백: 조작이 번거롭고 시각이 평범하다. 요구는 다섯 가지다.

1. 한 번 그리면 도구가 풀려 매번 다시 골라야 한다 → **연속 그리기**
2. 몇 번째 클릭인지 알 수 없다 → **진행 안내**
3. **수평선·수직선** 추가
4. **색·굵기** 변경
5. **"트레이딩뷰보다 특별한" 시각**

5번을 막연한 취향이 아니라 작업으로 바꾸는 근거가 코드 안에 이미 있다. 차트 본체는 정밀계기 규약을 쓴다 — 선폭 `CW = { hair:0.85, thin:1, base:1.25, bold:1.6, halo:1.2 }`, 점선 `CDASH = { fine:[1,3.5], std:[2,4], long:[4.5,4.5] }`("정밀 점선 — 가늘고 여백 넉넉 · 라운드캡과 함께 고급감", `forge-draw.js:35-36`), 라디우스 3토큰(`--r-sm:3px`·`--r-md:5px`·`--r-lg:7px`).

**1차 드로잉은 이 규약 밖에 있다** — 선폭 1.6(선택 2.2), 점선 `[4,3]`. 지표 작도 옆에서 혼자 굵고 투박하다. 고급화의 핵심은 장식 추가가 아니라 **기존 정밀 규약으로의 복귀**다.

## 2. 연속 그리기 + 진행 안내

### 2.1 연속 그리기

도구는 한 번 고르면 **무장 상태를 유지**한다. 도형을 완성해도 `_armed`를 비우지 않는다.

- 해제: `Esc`, 또는 팝오버에서 같은 도구를 다시 클릭(토글)
- 완성 시 `_finishNew()`는 `_drag`/`_newDraw`만 정리하고 `_armed`는 보존한다
- 선택 상태(`_selId`)는 완성한 도형으로 유지 — 방금 그린 것을 바로 다듬을 수 있다

### 2.2 진행 칩

플롯 좌상단 안쪽에 얇은 칩 하나. **도구가 무장 중일 때만** 표시한다.

```
추세선 · 시작점을 클릭하세요
추세선 · 끝점을 클릭하세요                  Esc 취소
평행채널 · 2/3 — 폭을 정할 지점을 클릭       Esc 취소
수평선 · 가격을 클릭하세요
```

문구는 `(_armed, _drag && _drag.stage, _newDraw && _newDraw.type)`에서 파생한다 — **새 상태를 만들지 않는다**. 캔버스에 그리므로 DOM 추가도 없다.

위치는 `padX + 10, padTop + 10`. 시연 HUD는 뷰포트 고정 `left:12px; top:66px`이므로 플롯 안쪽 좌상단과 겹치지 않는다(1차에서 툴바를 좌측에 두지 않은 것과 같은 이유).

## 3. 수평선 · 수직선

**클릭 한 번으로 완성**되는 도구 2종. `type: "hline"` / `"vline"`.

- **hline** — 앵커는 가격 하나(`a.p`). 창 전체를 가로지르는 선 + 우측 가격축 안쪽에 `284.50` 라벨
- **vline** — 앵커는 날짜 하나(`a.t`). 창 전체를 세로로 가로지르는 선 + 하단 시간축 위에 `26.03.14` 라벨

데이터 모델은 그대로 쓰되 `b`를 생략한다. 렌더·히트테스트·이동에서 `b` 부재를 분기한다.

- **히트**: 선 전체가 대상(`BODY_R = 5px`). 끝점 핸들은 없다
- **이동**: hline은 세로로만(`a.p`만 변경), vline은 가로로만(`a.t`만 변경). 다른 축은 고정
- **마그넷**: hline에 적용(고·저·시·종에 흡착). vline은 날짜라 무관

## 4. 색 · 굵기

선택된 도형 옆에 **스와치 줄**을 그린다(캔버스). ✕ 배지와 같은 무리에 배치한다.

- 색 5종: 골드 `#e8b463` · 청록 `#46c28e` · 적 `#e06a6a` · 청 `#5b8def` · 중립 `#8a92b2`
- 굵기 3단: `thin`(1) · `base`(1.25) · `bold`(1.6) — `CW` 값을 그대로 쓴다

저장은 `color`(hex 문자열)·`w`(`"thin"|"base"|"bold"`). **둘 다 선택적**이며 없으면 도구 기본색·`base`. 따라서 기존 그림은 손대지 않아도 그대로 열린다.

히트 우선순위: **✕ 배지 → 스와치 → 끝점 핸들 → 본체**. 작고 겹치기 쉬운 것이 먼저다.

## 5. 되돌리기

**`Ctrl+Z`(및 Mac `Cmd+Z`)만** 지원한다. **그리기 전용 스택**으로 보드 undo와 분리한다.

> **정정(2026-08-07)** — 최초 스펙은 `Ctrl+Shift+Z`(= `Ctrl+Y`)까지 적었으나 스택은 하나뿐이어서, 세 키가 모두 같은 `_undoPop()`을 호출했다. 다시실행을 기대하고 누르면 **되돌리기가 한 번 더 일어나 이력이 더 사라지는** 동작이었다(리뷰 실측). 사용자 결정으로 **다시실행은 구현하지 않고**, 오해를 부르는 `Ctrl+Shift+Z`·`Ctrl+Y` 바인딩을 뗀다 — Shift 조합은 `drawsKey`가 `false`를 반환해 브라우저로 통과시킨다. 다시실행은 후속 과제로 남긴다.

- 스냅샷 방식: 변경 직전 `DRAWS`의 깊은 복사를 스택에 push(최근 **30개**)
- 대상: 생성 · 삭제 · 전체 지우기 · 이동 · 끝점 조정 · 스타일 변경
- 문서 전환(`drawsLoad`) 시 스택을 비운다 — 다른 종목의 그림을 되살리면 안 된다
- **충돌 없음**: forge에는 보드 undo가 존재하지 않는다(`Ctrl+Z`는 현재 어디에도 바인딩돼 있지 않음 — 확인함). 따라서 Delete/Escape 때 필요했던 "보드에 양보" 규칙은 여기선 불필요하다. 입력 필드 포커스 중에는 종전대로 무시한다(브라우저 기본 실행취소를 뺏지 않기 위해)

스냅샷은 그림 수십 개 × 30단계라도 수십 KB 수준이고 메모리에만 산다(`dc.draws`에는 안 실린다).

## 6. 시각 고급화

### 6.1 정밀 규약으로 복귀

| 요소 | 1차 | 2차 |
|---|---|---|
| 선폭(평시/선택) | 1.6 / 2.2 | `CW.base 1.25` / `CW.bold 1.6` |
| 점선(박스) | `[4, 3]` | `CDASH.fine [1, 3.5]` + `lineCap:"round"` |
| 끝점 핸들 | 채운 5px 원 + 2px 링 | **속 빈 링**(반경 4.5·`CW.thin`) — 호버·드래그 시에만 채움 |
| 라벨 | 불투명 pill | 지표 라벨과 동일 — `600 11px`·자간 `-0.2px`·반투명 지면·라디우스 `--r-sm` |
| ✕ 배지 | 상시 또렷한 적색 원 | 평시 `alpha .45`, 호버 시 1.0 |
| 채널 채움 | 균일 10% | 기준선 → 바깥으로 **페이드**(예측 콘과 같은 어법) |

### 6.2 두 가지 차별점

**호버 예광** — 커서가 도형 판정 범위에 들면 선의 **알파만** 올린다(굵기 불변). 클릭 가능함을 두께 변화 없이 알린다.

호버 판정은 이미 매 `pointermove`마다 도는 `drawsCursor()`의 히트테스트 결과를 재사용한다(추가 계산 없음). 다만 **재드로는 호버 대상 id가 바뀔 때만** 한다 — 매 move마다 `drawsRender()`를 부르면 팬 중에도 그리기 레이어가 계속 다시 그려져 프레임을 갉아먹는다. 이 조건이 지켜지는지는 검증 항목에 포함한다.

**선택은 굵기가 아니라 헤일로** — 선택된 도형은 선 아래에 반투명 광(`CW.halo 1.2`, alpha .18)을 한 겹 깔아 떠오르게 한다. 트레이딩뷰는 선택 시 선이 굵어지고 핸들이 커지는데, 그 반대로 간다 — **굵기는 데이터의 것이고, 상태는 빛으로 말한다**.

색은 하드코딩하지 않고 `FC_GOLD`·`FC_BULL`·`FC_BEAR`·`FC_CHART_BG` 전역을 경유한다(테마 추종, 1차 M3와 같은 이유).

## 7. 저장 포맷

```js
{ id, type:"trend"|"channel"|"range"|"period"|"hline"|"vline",
  a:{t,p}, b?:{t,p}, off?:number, color?:string, w?:"thin"|"base"|"bold" }
```

`b`·`off`·`color`·`w` 전부 선택적. **기존 그림 100% 하위호환** — 마이그레이션 없음.

## 8. 검증

**단위테스트(`node --test forge-tools.test.js`)** — 순수 함수만.
1. undo 스택: push/pop, 30개 상한, 빈 스택 pop
2. 스타일 병합: `color`·`w` 없으면 도구 기본값, 있으면 그 값
3. hline/vline 앵커 왕복(`b` 없는 도형이 tToFi/fiToT를 안 거치는지)

**헤드리스 실화면**
4. 연속 그리기 — 도구 한 번 고르고 3개 연속 생성, 무장 유지
5. 진행 칩 문구가 단계에 따라 바뀌는지
6. hline·vline 1클릭 완성, hline은 세로로만·vline은 가로로만 이동
7. `Ctrl+Z` 4종(생성·삭제·이동·스타일) 복원
8. **하위호환** — `color`·`w` 없는 기존 포맷 그림이 정상 렌더
9. 무회귀 — 그림 0개·무장 없음이면 `drawsPointerDown` `false`(팬 유지)
10. 호버 재드로 억제 — 같은 도형 위에서 마우스를 계속 움직여도 `drawsRender` 호출이 늘지 않는지(호출 카운터로 확인)

**스크린샷 육안 대조** — 지표 작도(추세선·피보)와 나란히 두고 선폭·점선·라벨이 같은 언어인지. 1차에서 픽셀 수만 보고 판단했다 틀린 적이 있으므로 **반드시 눈으로 본다**.

**규율** — 라이브 검증은 읽기 경로만(`loadTicker`·`_addTickerDoc` 금지).

## 9. 범위 밖 (YAGNI)

- 도형 복제·잠금·그룹
- 텍스트 메모·화살표·피보 도구(피보는 이미 지표)
- 스타일 프리셋 저장
- 모바일 터치 그리기(1차와 동일하게 데스크톱 전용)
- 보드 undo와의 통합 — 별도 스택 유지가 더 안전하다
