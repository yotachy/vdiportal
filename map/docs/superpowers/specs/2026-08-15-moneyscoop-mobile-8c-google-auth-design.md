# 머니스쿱 모바일 8c — 구글 로그인 + 익명 계정 병합

> 대상: `map/mobile/` + `map/wallet-*.php` · 설계일 2026-08-15
> 선행: Phase 8b(`2026-08-13-moneyscoop-mobile-phase8b-design.md`) · `mobile/docs/design_handoff/SPEC-economy.md` §4

## 왜

재설치하면 지갑이 사라진다. `SPEC §4` 가 이 페이즈를 "익명 먼저, 그다음 연결"로 정의했고,
`accounts.google_sub` 컬럼은 **8b 가 이미 만들어뒀다**(현재 미사용).

역방향 구멍도 같이 닫힌다 — 재설치하면 5개를 또 받는다. 지금은 IP 상한(`W_IP_DAILY`)으로만
완화돼 있고, `SPEC §4` 자신이 "출시 시점 가장 유력한 남용 경로"라고 지목한 자리다.

## 정하고 들어가는 것

| 결정 | 값 | 근거 |
|---|---|---|
| 병합 시 잔량 | **첫 병합만 이전. 두 번째 기기부터는 익명 잔량을 버린다** | `SPEC §4` 원문("항상 높은 쪽")은 래칫을 만든다 — 기기를 바꿔가며 익명 5개를 받고 로그인하면 잔량이 계속 오른다. 8d(광고 수익)가 붙으면 실제 비용이 된다. 버린 수량은 원장에 남겨 문의에 답할 수 있게 한다 |
| 스트릭 | **항상 긴 쪽** | 화폐가 아니라 습관 기록이다. 래칫으로 악용할 것이 없다 |
| 노출 위치 | **지갑 화면에만** | 잔량을 신경 쓸 때만 눈에 들어온다. 8d 광고 줄도 같은 화면이라 한 곳에 모인다. 안내 배너·소진 시 권유는 넣지 않는다 |
| 동기화 범위 | **지갑만**(잔량·스트릭). 워치리스트는 기기별 | 8c 를 돈 문제에만 집중시킨다. 지갑 화면에 "종목 목록은 기기별로 유지됩니다" 한 줄로 솔직하게 알린다 |
| 네이티브 | **쓰지 않는다** | 안드로이드 빌드가 한 번도 안 돌았다. 딥링크(`moneyscoop://`)는 `AndroidManifest` 인텐트 필터가 필요해 8c 를 빌드에 묶는다 — 논스+폴링으로 그 의존을 없앤다 |
| 로그아웃 | **v1 에 포함.** 계정 토큰을 버리고 기기 토큰으로 복귀 | 익명 상태로 돌아간다. 로그인이 되돌릴 수 없는 문이면 안 된다 |

## 1. 핸드셰이크 — 논스 + 폴링

구글 OAuth 는 브라우저 리다이렉트로 끝나는데 그 결과를 앱으로 되돌려야 한다. 딥링크 대신
서버에 논스를 두고 앱이 폴링한다. 개발 브라우저에서도 Capacitor 웹뷰에서도 동일하게 돈다.

```
앱                          서버                        구글
 │  authStart (기기 토큰)      │
 ├───────────────────────────▶│  논스 발급(단회용·10분)
 │◀── nonce + authUrl ────────┤
 │                            │
 │  브라우저를 authUrl 로 연다 ─────────────────────────▶│
 │                            │◀── code + state ────────┤
 │                            │  토큰 교환 → 이메일 → sub
 │                            │  논스에 google_sub 기록
 │                            │  "앱으로 돌아가세요" 페이지
 │  authPoll (기기 토큰+논스)   │
 ├───────────────────────────▶│  병합 실행 → 계정 토큰 발급
 │◀── 계정 토큰 + 잔량 ────────┤
```

기존 `map/forge-auth.php`(PC용, 64줄)가 authorization-code 왕복을 이미 전부 한다 — state CSRF
검증, 토큰 교환, `id_token` 페이로드에서 이메일 추출까지. 신규 `map/wallet-auth.php` 는 그 흐름을
그대로 쓰되 **쿠키 대신 논스에 결과를 적는다.** 클라이언트 자격증명(`forge_google_oauth.json`)도
공유한다 — 두 벌이 되면 갈린다.

**폴링 보안.** 논스는 발급 시 기기에 묶이고 `authPoll` 은 기기 토큰을 함께 요구한다. 남의 논스를
주워도 못 쓴다(401). 단회용이며 10분 만료.

**토큰 승계.** 현재 베어러는 `device_id` 에 묶여 있어(`w_token_read`) 기기 B 가 구글 계정을 보려면
다른 계정을 가리켜야 한다. 토큰에 주체 종류를 붙인다 — `d:` 기기 / `a:` 계정. **접두가 없는 기존
토큰은 기기로 읽어 하위 호환을 유지한다**(배포 시점에 살아 있는 토큰이 깨지면 안 된다).

## 2. 병합 — 두 갈래뿐

로그인한 `google_sub` 으로 기존 계정 행을 찾는다.

**(a) 없다 — 첫 병합.** 지금 쓰던 익명 계정 행에 `google_sub` 을 박는다. 잔량·스트릭·원장이
통째로 그대로 남는다. 옮기는 것이 아니라 **그 계정이 곧 구글 계정이 된다.** 원장에 `merge_claim`
한 줄(delta 0, 기록용).

**(b) 있다 — 두 번째 이후 기기.** 익명 잔량은 버린다. 익명 계정에 `merge_discard` 를 **delta
음수**로 적어 잔량을 0으로 내린다 — 이렇게 해야 `SUM(delta)` 가 계속 진실이다(8b: `accounts.balance`
는 복구 가능한 캐시일 뿐, 진실은 원장의 합). 구글 계정 쪽엔 `merge_from` 한 줄(delta 0)에 버려진
수량과 기기 계정 id 를 `ref` 로 남긴다. **"5개가 어디 갔냐"는 문의에 답할 근거가 이 두 줄이다.**

스트릭은 (b)에서도 긴 쪽을 취한다.

이후 그 기기의 `authPoll` 응답은 계정 토큰(`a:`)이며, 앱은 기기 토큰을 지우지 않고 **함께 보관한다**
— 로그아웃이 기기 토큰으로 복귀하는 경로이기 때문이다.

## 3. 스키마 v3

프로덕션 SQLite **3.26.0** — `RETURNING`·`STRICT`·`ALTER TABLE ... DROP COLUMN` 사용 불가.
`accounts.google_sub` 은 이미 존재한다. 추가는 둘:

```sql
create table if not exists auth_nonce (
  nonce TEXT PRIMARY KEY, device_id TEXT NOT NULL, google_sub TEXT,
  created_at TEXT NOT NULL, used INTEGER NOT NULL DEFAULT 0);
create unique index if not exists ix_accounts_gsub on accounts (google_sub);
```

SQLite 의 유니크 인덱스는 `NULL` 을 서로 다른 값으로 취급하므로, 미연결 계정이 여럿 있어도 걸리지
않는다. 이 인덱스가 **동시 병합의 최종 방어선**이다 — 두 기기가 같은 구글 계정으로 동시에 (a)를
시도하면 하나만 성공한다.

마이그레이션은 8b 와 같이 트랜잭션 안에서, 재실행 가능하게 쓴다.

## 4. 서버 op

`wallet-api.php` 에 **둘**을 더한다. 둘 다 기기 토큰을 요구한다.

| op | 입력 | 동작 |
|---|---|---|
| `authStart` | 기기 토큰 | 논스 발급 + `authUrl` 반환 |
| `authPoll` | 기기 토큰 + `nonce` | 미완이면 `{pending:true}`. 완료면 병합 실행 → 계정 토큰 + 상태 |

**로그아웃 op 는 없다.** 앱이 계정 토큰을 버리고 기기 토큰으로 돌아가면 그만이고, 서버가 할 일이
없다. 아무것도 안 하는 엔드포인트를 두면 나중에 읽는 사람이 무언가 한다고 믿는다.

병합은 8b 규율 그대로 — `BEGIN IMMEDIATE` + `busy_timeout`. 멱등키는 `merge:<google_sub>:<device_acct>`
를 접두로 쓰되 **줄마다 접미를 붙인다**(`:claim` / `:discard` / `:from`) — `ledger.idem` 이 UNIQUE 라
한 키로 두 줄을 쓸 수 없다. 같은 논스를 두 번 눌러도 한 번만 실행된다.

`wallet-auth.php`(신규, 브라우저용)는 `GET` 두 경우만 처리한다: `?nonce=…`(구글로 리다이렉트) /
`?code=…&state=…`(콜백 → 논스에 기록 → "앱으로 돌아가세요"). 앱은 이 파일을 직접 부르지 않는다.

## 5. 실패 처리

OAuth 실패·사용자 취소·타임아웃 — **전부 앱은 익명 상태 그대로다.** 로그인은 부가 기능이지
관문이 아니다(온보딩 3단계의 지급 실패와 같은 원칙). 폴링은 10분 뒤 포기하고 "다시 시도"를 보여준다.

`forge_google_oauth.json` 이 서버에 없으면 `authStart` 는 `{ok:false, reason:"auth-disabled"}` 를
돌려주고, 지갑 화면은 로그인 행 자체를 숨긴다 — PC 쪽 `fauth_enabled()` 와 같은 무중단 스위치다.

## 6. 검증

8b 에서 세운 두 하네스를 확장한다. **새 하네스를 만들지 않는다.**

| 검사 | 왜 |
|---|---|
| 같은 구글 계정으로 **두 기기가 동시에** 첫 병합 | 유니크 인덱스가 DB 층에서 막는지 실측. 앱 층 검사만으로는 경합에서 두 계정이 생긴다 |
| 남의 논스로 `authPoll` → 401 | 논스가 기기에 묶여 있는지. 안 묶이면 논스만 알면 남의 계정을 탈취한다 |
| 같은 논스 두 번 → 두 번째는 거부 | 단회용. 재사용되면 병합이 두 번 돈다 |
| 병합 후 `SUM(delta)` == `balance` | (b)의 `merge_discard` 가 음수로 안 적히면 원장과 캐시가 갈린다 |
| 두 번째 기기 병합 뒤 구글 잔량이 **안 오른다** | 래칫 방지의 핵심. 이 검사가 없으면 "높은 쪽" 로직이 조용히 되살아난다 |
| 접두 없는 옛 토큰이 여전히 기기로 읽힌다 | 하위 호환. 배포 순간 살아 있는 토큰이 깨지면 안 된다 |
| `forge_google_oauth.json` 없을 때 로그인 행이 숨는다 | 무중단 스위치 |

`map/tests/run.sh` 의 `wallet`·`wallet-dispatcher`·`concurrency` 에 붙는다. 모바일 스위트는
지갑 화면 행 추가분만 움직인다.

**기대값은 구현 상수가 아니라 밖에서 쓴다** — 이 저장소에서 반복해 재발한 실패 모양이다.

## 7. 범위 밖

- **워치리스트 동기화** — 지갑 화면에 "종목 목록은 기기별로 유지됩니다" 한 줄만. 별도 페이즈
- **애플 로그인** — 안드로이드 단독 출시
- **계정 삭제 / 데이터 내보내기** — 스토어 정책상 언젠가 필요하나 8c 밖
- **이메일 외 프로필** — 이름·사진 안 받는다. 스코프는 `openid email` 뿐(PC 와 동일)
- **로그인 유도 UI** — 잔량 소진 시 권유, 온보딩 내 로그인. 지갑 화면 한 행뿐
