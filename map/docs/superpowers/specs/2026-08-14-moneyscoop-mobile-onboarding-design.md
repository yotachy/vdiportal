# 머니스쿱 모바일 — 온보딩 5단계 (시안 3a·3b)

> 대상: `map/mobile/` · 설계일 2026-08-14
> 선행: Phase 8b(`2026-08-13-moneyscoop-mobile-phase8b-design.md`) · `mobile/docs/design_handoff/README.md` §1

## 왜 지금인가 — 빠져 있었다

시안에는 온보딩이 5단계로 있다(`#3a` `#3b`). 백로그에서 그 이름이 나오는 곳은 **딱 한 줄** —
`＋ Add ticker` 항목의 *"온보딩 페이즈와 함께"* 이고, **그 페이즈는 존재한 적이 없다.**
없는 페이즈에 의존성을 걸어둔 채 8b 까지 왔다.

페이즈를 기술 위험 순서로 잡은 결과다 — "엔진이 폰에서 도는가"(0) → "핵심 루프가 도는가"(1) →
차트(2~4) → 화면 정합(5~7) → 지갑(8a·8b). 전부 *분석이 되는가* 를 묻는 축이고,
**"새 사용자가 처음 무엇을 만나는가"는 어느 페이즈의 질문도 아니었다.** 그래서
`store.js` 의 하드코딩 시드 3종(AAPL·NVDA·MSFT)이 임시가 아니라 사실상 기본값으로 굳었다.

지금 보이는 3종은 **있어야 할 화면의 대체물**이다. 그리고 이 누락은 폴리시 문제이기도 하다 —
시안 5단계의 UMP 동의는 AdMob 정책상 EEA·영국·캐나다에 필수이므로, **온보딩 없이는 8d(광고 수익)를
출시할 수 없다.** "나중에 다듬을 것"으로 분류돼 있었지만 실제로는 수익화의 선행 조건이다.

## 정하고 들어가는 것

| 결정 | 값 | 근거 |
|---|---|---|
| 5단계 범위 | **위험 고지 + 약관 체크박스만.** UMP·크래시 토글은 8d | UMP 는 AdMob SDK 기능이고 안드로이드 빌드가 한 번도 안 돌았다. 동의 화면은 법적 효력을 갖는 자리라, 실제로 아무 일도 안 하는 토글을 진짜처럼 보이게 두지 않는다 |
| 5스쿱 지급 시점 | **3단계 진입 시 첫 `hello`** | 시안이 "광고가 나오기 전에 경제를 설명하고 거기서 지급"이다. 1~2단계 이탈자는 계정이 안 생겨 IP 상한도 안 쓴다 |
| 지급 실패 | **진행을 막지 않는다** | 네트워크 하나로 앱이 안 열리면 안 된다. Basic 리포트는 무료라 앱은 쓸 수 있다 |
| 1·2단계 데이터 | **번들 시계 + 진짜 엔진** | 첫 화면이 네트워크에 달리면 안 된다(콜드 수신 실측 942ms). 숫자는 엔진이 낸 진짜 값이고 데이터만 고정 — 삽화가 아니라 데모다 |
| 4단계 컴포넌트 | **`＋ Add ticker` 의 `prompt()` 를 대체** | 백로그가 둘을 묶어뒀다. 온보딩만 예쁘게 만들고 본 화면은 `prompt()` 로 두는 건 앞뒤가 안 맞는다 |
| 슬롯 과금 | **범위 밖** | `slot`(1스쿱)이 가격표에 있으나 호출부가 없다. 잔량 5로 시작한 사용자가 종목 하나에 1을 쓰는 균형은 실사용을 보고 정한다 |

## 1. 파일과 게이트

```
www/screens/onboarding.js   MSOnboarding — 5단계. 자체 스텝 상태를 들고 셸 밖에서 돈다
www/ticker-picker.js        MSTickerPicker — 큐레이션 그리드 + 직접 입력. 4단계와 ＋Add 공용
www/onboarding-sample.json  번들 시계(240봉). 1·2단계가 이걸로 엔진을 돌린다
```

`app.js` 부팅:

```
DOMContentLoaded
  → 지갑 백엔드 설치 (지금과 동일. 단 hello 는 여기서 안 나간다)
  → MSStore.onboarded() ?  아니오 → MSOnboarding.render(rootEl)   셸을 안 그린다
                           예   → renderShell()  (현행)
```

**`seedIfEmpty()` 는 부팅에서 빠진다.** 4단계가 그 자리다. `MSStore.SEED` 는 큐레이션 목록의
기본 선택으로 남는다(시안 4단계가 *"3 pre-selected"*).

## 2. 지갑과의 이음매

```
1·2단계  네트워크 0. 계정 없음
3단계    진입 시 hello → 계정 생성 + 서버가 5개 지급 → 화면이 그 값을 표시
         실패 시: "지금은 연결되지 않았습니다" + 다시 시도. 그대로 4단계로 갈 수 있고
                 지갑은 "사용 불가"로 남는다
4·5단계  네트워크 0
```

화면이 "5개를 드렸습니다"라고 말할 때 **그 5는 서버가 실제로 준 값**이다. 클라이언트가 5를
그려놓고 나중에 맞추는 것이 아니다 — 8b 의 "클라이언트는 잔량을 계산하지 않는다"가 여기에도 적용된다.

뒤로 가기는 허용한다. 3단계로 되돌아가도 `hello` 는 기존 계정을 돌려줄 뿐 다시 지급하지 않는다
(`accounts.device_id UNIQUE` 가 DB 층에서 막는다 — 8b Task 2 에서 실측 확인).

## 3. 다섯 화면

**1 — 콜드 오픈.** 번들 시계로 실제 차트 + 예측 콘. 헤드라인 `Where does this chart go next?`
하단 5칸 진행 표시(활성 칸만 골드).
**시안의 언어 칩(🌐 EN)은 넣지 않는다** — 로케일 전환은 백로그가 v1 밖으로 미뤄둔 항목이라,
넣으면 눌러도 아무 일 없는 죽은 컨트롤이 된다.

**2 — 작동 원리.** 같은 시계로 `MSIndicators.readings()` 를 돌려 **막대 30개**를 중앙선 기준
위/아래로 그리고, 하나의 판정 바로 접힌다. 시안은 32라고 적었지만 방향을 물을 수 있는 것은 30종이다
(`trend`·`phasefold` 는 bias 를 안 준다) — REASONING 에서 `30 with a direction` 으로 정리한 것과
같은 규율을 쓴다.

**3 — 왜 무료인가 + 지급.** Earn/Spend 표. 가격은 `MSWallet.COSTS` 에서 읽는다(지갑 화면과 같은 출처).
진입 시 `hello`.

**4 — 첫 종목.** 큐레이션 그리드, `MSStore.SEED` 3종 미리 선택. 직접 입력은 기존 `suggest`
경로 재사용(`api.js` 가 `notfound` 시 후보 6개를 이미 받는다). **최소 1개**를 골라야 넘어간다 —
빈 워치리스트 이탈 방지가 이 단계의 존재 이유다.

**5 — 위험 고지 + 약관.** 읽을 만한 본문 + 필수 체크박스. 마지막 줄 `Your first deep analysis is free.`
완료 시 `MSStore.setOnboarded()` 와 함께 **동의 사실을 기록**한다 — 동의한 약관 버전 문자열과
동의 시각(ISO8601). 체크박스의 불리언만 남기면 약관이 개정됐을 때 누가 무엇에 동의했는지 말할 수 없다.
서버로는 보내지 않는다(8c 에서 계정에 붙일 자리다).

## 4. 검증

이번 페이즈에서 조용히 깨질 수 있는 것들을 관문으로 세운다.

| 검사 | 왜 |
|---|---|
| **온보딩 중 네트워크 호출은 3단계의 `hello` 하나뿐** | 가짜 `fetch` 로 전 단계를 통과시키며 호출을 센다. 1·2단계가 번들을 안 쓰고 네트워크를 타기 시작하면 첫 화면이 느려지는데 눈으로는 "좀 느리네"로만 보인다 |
| 완료 플래그 없으면 온보딩, 있으면 셸 | 게이트 자체 |
| 부팅에서 `seedIfEmpty()` 가 사라졌다 | 남아 있으면 4단계가 무의미해지고 사용자가 안 고른 종목이 생긴다 |
| 4단계가 고른 것과 **정확히 같은** 목록이 심긴다 | 미리 선택된 3종을 해제했는데도 남는 종류의 결함 |
| 약관 미체크면 완료 불가 | 법적 효력이 있는 자리 |
| `hello` 실패해도 4·5단계로 진행된다 | 네트워크 하나로 앱이 못 열리면 안 된다 |
| 뒤로 가서 3단계 재진입해도 잔량이 두 번 늘지 않는다 | 지급 멱등 |
| `prompt()` 잔재가 없다 | `＋ Add` 가 새 컴포넌트로 완전히 교체됐는지 |

`map/tests/run.sh` 의 `moneyscoop-mobile` 스위트에 붙는다. 서버를 안 건드리므로
`wallet`·`wallet-dispatcher`·`concurrency` 는 **무변동**이어야 한다.

**기대값은 구현 상수가 아니라 밖에서 쓴다** — 이 저장소에서 반복해 재발한 실패 모양이다.

## 5. 범위 밖

- **슬롯 과금**(4번째 종목부터 1스쿱) — 균형은 실사용 후
- **언어 시트·로케일 전환** — v1 밖. 1단계의 언어 칩 자리는 비워 둔다
- **UMP 개인화 광고 토글 · 크래시 리포트 토글** — 8d(AdMob)
- **온보딩 재실행 경로**(설정에서 다시 보기) — 필요해지면
- **번들 시계의 종목 정체** — 실제 종목명을 쓰지 않고 `예시 시계`로 표기한다. 특정 종목의
  과거 차트를 첫 화면에 두면 추천으로 읽힐 수 있다
