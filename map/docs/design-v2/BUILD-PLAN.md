## 1. 목표

시안2를 **동작 수준까지 그대로** 구현한 머니스쿱 모바일 앱. 화면·동선·상태·카피·모션은 프로토타입이 정답이고,
그 안의 차트 계산·판정·수치(연출용 더미)를 **스쿱 엔진 실출력**으로 치환한다(치환표 42항목).
분석 3단계 = 기본(무료·5지표·채점 제외) / 심화(◈2·32지표+프리셋 9종) / 커스텀(◈3·+가중치+페르소나).

## 2. 개발 위치 · 격리 (사용자 지시 2026-08-24)

- **신규 디렉토리 `map/app/`** 에서 진행. 배포 시 `www/map/app/`.
- `_archive/`(봉쇄) · `map.html`(무관) · `forge.html`(엔진 작업대) · `potflow/`(독립 트랙)과 **파일·커밋 스코프 불간섭**.
- 엔진은 **`map/forge-core.js` · `map/forge-tools.js` 원본을 상대경로 `<script src="../forge-core.js">` 로 참조** — 사본 금지(§②).
- 서버 재사용: `forge-api.php`(OHLC 프록시) · `wallet-lib/api/ssv.php`(스쿱 원장·광고 SSV·구글 로그인·게스트 병합).
- 커밋 스코프: `app:` 접두(예: `feat(app): …`). 엔진을 건드리는 커밋은 기존 규율(§② 엔진 변경 프로토콜) 그대로.

## 5. 엔진 브리지 계약 (`app-engine.js`) — 심장 이식 지점

앱 쪽에서 본 엔진의 전부. **엔진 로직 수정 없음** — 어댑터가 ForgeCore 출력을 화면 계약으로 정규화한다.

```js
MS.engine.analyze(req, onProgress) → Promise<Report>
// req = { symbol, tf:'일'|'주'|'월', tier:'basic'|'deep'|'custom',
//         preset:프리셋명, weights:{지표:배율}, personaApply:bool, personaVec, candles }
// onProgress(ev) — ev = { index, indicatorId, group, done:32 } : 지표 하나 계산 완료마다.
//   app-run 연출이 이 이벤트에 박자 동기화(지침서 §4 — 프로토 420ms 데모 박자 대체).
//   계산이 연출보다 빠르면 연출 최소 박자로 큐잉, 느리면 대기 — 연출은 절대 계산을 앞지르지 않는다.
// Report = {
//   verdict:   { dir, prob, target, range:[lo,hi], invalid(무효선), score },   // R-B02
//   indicators:[{ id, name, group, bias, strength, text }],                    // 32종(basic 5)
//   horizons:  [...],                       // 시점별 예측(hz 세그)
//   cone:      { ... },                     // 신뢰콘·신뢰지평 감쇠(R-B05)
//   paths:     { p1, p2, p3 },              // 예측선 — p2/p3 는 재계산 실좌표(R-B06, 프로토 translate 대체)
//   drawings:  { 지표id: 오버레이 기하 },     // 작도(collectAnchors/Levels·analyze* 산출)
//   regime, engineVersion }
```

- **차트·작도 품질 하한(2026-08-24 사용자 확정)**: **모바일 차트와 작도는 PC 웹버전과 동일해야 한다 — 이것이 최소 품질 기준**. 작도 기법·기하는 forge-draw.js 의 per-indicator 렌더링(움직이는 밴드·구름·채널·레벨 등)과 동일 의미로 이식하고, 핀치줌·드래그 팬도 웹과 같은 감각(지침서 §5). 모바일용 단순화·요약 금지 — 달라질 수 있는 것은 배치(세로)뿐. P2 차트 작업의 합격선.
- **티어→블록셋**: basic = Lv1 5종(ma·macd·rsi·bollinger·volume ≡ 시안 IND 앞 5) / deep·custom = `IND_TIERS` 32종 전체.
- **프리셋 9종**: 시안 `PROF`(5축 배분 — 01 §3-1)를 지표 가중 프로필로 매핑. 서버 정의·엔진 버전과 함께 버저닝(R-B03).
- **가중치·페르소나**: 커스텀의 지표 배율(0~3)과 페르소나 보정을 엔진 재계산으로 반영. 보정 알고리즘 자체는 엔진 몫(§15 협의) — 브리지는 입력 전달만.
- **지표 명명 정합**: 시안 IND 32 ↔ 엔진 `IND_TIERS` 32 매핑표를 P2에서 확정. **불일치 2건**(시안: RSI 다이버전스·거래량 다이버전스 ↔ 엔진: phasefold·pattern)은 협의 대상(§9-Q5). 엔진이 정본.
- **채점 판정**: PC 엔진 백테스트의 방향 판정 규칙과 반드시 합치(§15). 판정 로직은 서버(§6)로 — 클라는 표시만.

## 6. 데이터 · 서버 계층 — 치환표 42항목의 3층 배치

| 층 | 담당 | 치환표 |
|---|---|---|
| 엔진(클라, forge-core) | 지표·판정·예측선·콘·가중치·페르소나 반영 계산 | R-B01·02·05·06 |
| 클라 데이터(app-data) | OHLC(forge-api 프록시)·스파크라인(실봉 파생)·캘린더 분기 | R-A02~05, R-J01 |
| **서버(신규 `app-api.php`)** | 아래 API 일습 | 나머지 전부 |

신규 서버 API(모두 멱등키·서버 시각 — 치환표 전역 규칙):

1. **config** — 정책 테이블 서빙(리모트 컨피그). §8 기준선이 초기값.
2. **predictions(채점 원장)** — 분석 완료 등록(종목×주기, 그날 마지막 1건 규칙)·목록·집계(주별/일별/주기별)·**채점 배치**. cafe24 에 cron 이 없으므로 **read-시 지연 채점**(만기 지난 미채점 건을 요청 처리 시 채점) + 시장 기준선 주기 재계산. 원장 영구 보존·화면 노출 90일.
3. **signals** — 감지 피드(보관 3일·20+10)·읽음 동기화. 감지 룰은 엔진 지표 기반(임계는 config — §15 협의).
4. **persona** — 질문 은행(서버 500+ 목표·초기 15문)·답변 저장(하루 5답·마지막 1건 고치기)·프로파일 벡터.
5. **stats** — 익명 집계(사용량·인기 종목·프리셋 분포·관점별 적중률)·리더보드(30일·30회 조건)·내 순위.
6. **wallet 확장** — 기존 3종 재사용 + 개정: 비용 `full 3→deep 2 / custom 5→3`, 상한 `15+(레벨−1)×2`, **XP·레벨 테이블 신설**(적립 서버 판정 — §15), 출석 6h·연속 7일·광고 +3 정합. `./tests/run.sh concurrency` 관문 유지.
7. **sync** — 계정별 상태 동기화(관심종목·분석 슬롯·페르소나·설정), 게스트 병합은 기존 `w_merge` 확장(R-I02).

서버 데이터 파일은 `.htaccess` 차단 필수([[cafe24-data-files-publicly-readable]]) · POST <128KB · 배포 불가침 목록에 신규 DB 추가.

## 10. 검증 관문 체계

1. **`./tests/run.sh` 전량** — app 스위트 신설(P0): config·state·engine 브리지의 node 테스트 + ES2017 문법 하한 테스트. 기대값은 구현 밖에서.
2. **헤드리스 시각 대조** — 화면 태스크마다 프로토타입과 나란히 스크린샷(§④-2: 리뷰도 시각을 본다). WSL playwright([[headless-verify-wsl]]).
3. **브라우저 관문** — 전역 충돌 감시용 gate 신설(§① — 노드 테스트는 전역 충돌을 원리적으로 못 봄). `run.sh browser` 스코프에 편입.
4. **지갑 배포 전 `run.sh concurrency`** — 기존 규율 유지.
5. **엔진 정합** — 같은 입력이면 PC(forge.html)와 동일 판정(§⓪-2). P2부터 브리지 비교 테스트로 상시 확인.
