## 2. 영속화 계약 — localStorage `ms_proto_v1`

### 2-1. 저장 (persist — L2266)

`localStorage.setItem('ms_proto_v1', JSON.stringify({...}))`. try/catch 감쌈. 축약키 매핑:

| 축약키 | state 필드 | 비고 |
|---|---|---|
| `p` | `pickArr` | |
| `a` | `analyzed` | |
| `at` | `analyzedAt` | |
| `s` | `scoops` | |
| `t` | `theme` | |
| `g` | `gLinked` (`?1:0`) | |
| `q` | `pQi` | |
| `pa` | `pAns` | |
| `x` | `xp` | |
| `xt` | `xpToday` | |
| `fz` | `fz` (`?1:0`) | |
| `dv` | `dVisit` | 일일 미션·XP 한도 기록 포함 |

**저장 시점**: ① `componentDidUpdate`에서 `pickArr/analyzed/scoops` 참조 변경 시 자동(L2203) ② 상태 변경 핸들러 곳곳에서 `setTimeout(this.persist, 80~120)` 수동 호출(L2204, 2210, 2212~2213, 2216, 2222, 2227, 2233, 2265, 2272, 2274, 2276, 2435, 2690, 2740, 2742, 2788, 2800~2802, 2824, 2884 등).

**영속되지 않는 것(전부 세션 휘발)**: `wts`·`chk`(커스텀 가중치/체크), `indOff`·`drawOff`(작도 토글), `sigRead`, `xpG`, `yOpen`·`sgOpen`, `strk7`(연속 방문), `stkOpN`(종목 변경 6회 한도), `stkXpN`(종목 추가 XP 3회 한도), `pqDay`(페르소나 일 5답 카운터), `preset`, `tier`, `sigN`/`gN`, `notiOff`. → "일일 한도"라고 문구에 적힌 것 중 `stkOpN`·`stkXpN`·`pqDay`·`strk7`은 저장 안 되므로 실제로는 **앱 재시작 시 리셋**(dv에 든 `dw`·`login`·메뉴 방문·`ax_*`만 진짜 일 단위 유지).

### 2-2. 복원 (componentDidMount — L2202)

- `JSON.parse(localStorage.getItem('ms_proto_v1')||'null')`. `v && v.p && v.p.length`일 때만 복원 → **관심 종목이 비면 저장분 전체 무시**(첫 방문 취급, `screen:'boot'` 유지).
- **24h 만료 필터**: `analyzed`는 `at[k]`가 없거나 `Date.now()-at[k] < 86400000`인 키만 살려서 복원(`analyzedAt`은 원본 그대로 보존 — 만료 표시는 `vExp`가 계산, L2308).
- 복원값 보정: `scoops`는 number 아니면 15, `theme`는 `'light'` 외엔 `'dark'`, `pAsk`는 `pQi>0`이면 0, `xpToday`는 `dv.d===오늘`일 때만 복원(아니면 0), `ticker=v.p[0]`, `screen:'dash'`로 직행.
- body에 `data-th` 재설정, 1.4s 뒤 `visitXp('dash')`(오늘 첫 방문 XP 트리거).
- **리셋** (L2918): `localStorage.setItem('ms_proto_v1','null')` + state를 초기 유사값으로(`screen:'boot'`, `pickArr:[]`, `scoops:15` 등).

또 하나의 카운트다운: `componentDidMount`의 1초 인터벌이 `left`·`gLeft`를 감소(문서 hidden이면 정지 — L2202).

## 5. 파생 계산 — 어떤 함수가 어떤 더미를 만드는가

모두 `build()`(L2144~2200) 안. `this._m`에 1회 캐시(시드 결정적 → 항상 같은 그림).

- **`R(seed)`** (L2146): 파크-밀러 LCG(`x*16807 % 2147483647`) 기반 결정적 난수 생성기. 모든 합성이 이것 위에 있어 **재현 가능**.
- **`walk(sd,n,dr,vo)`** (L2148): 시드 랜덤워크. `a[i]=a[i-1]*(1+dr+(r()-0.48)*vo)`, 시작 100, 하한 1. `-0.48`(0.5 아님)이라 미세한 상향 바이어스 내장.
- **`chart(o)`** (L2149~2187): 411×411 SVG용 캔들 56봉 + 예측 요소 일괄 합성. 종가열을 `last`에 맞게 스케일 → OHLC 합성(고저는 ±0.6% 난수 — L2153) → 산출물: 캔들 path(`ub/db/wk`), 예측 콘(`cone`, 내부 50% `cin`), 1차 예측선 2분할(`p1a/p1b`, 목표 곡선 `0.18t+0.82t²` 이징 — L2165, 분할점 55%), MA(8봉 `ma1`), 일목 구름(`cloud`=MA6/MA24 사이 면), 볼린저(`bu/bd`, 18봉 창, ±1.9σ — L2173), 피보나치(`fy382/fy618`), 회귀채널(`chU/chD`, 최소자승+최대편차×0.85, 1.72배 연장 — L2177~2182), 신뢰 레일(`rail`, 19눈금), 당일봉(`tod`, `today` 옵션). 과거 구간은 폭의 58%(`pastW` — L2150), `frac` 옵션으로 캔들 일부만(run 화면 0.78).
- **`spark(sd,dr,vo)`** (L2188): 60포인트 워크 → 84×22 정규화 폴리라인(종목 카드 미니 차트).
- **`dashS`** (L2194): 종목별 30포인트 워크(seed+55, dr×1.1, vol×0.8 하한 0.008) — 대시보드 평균 흐름의 원료.
- **`dashD(picks)`** (L2195): 선택 종목들의 `dashS`를 각자 시작점 대비 정규화해 평균 → 347×72 라인/area path + 등락 % + 끝점 좌표. 홈 히어로의 "내 종목 평균 흐름".
- **`HSPK`** (L2324): 같은 원료의 최근 14포인트(i=16~29)만 86×20으로 재정규화한 헤더/카드용 축약 스파크.
- **주·월봉** (L2192~2193): 별도 데이터 없이 일봉 파라미터를 배율(§3-2)로 부풀린 **재합성** — 시드가 달라 모양도 다름.
- **채점 집계** (L2348~2361 `GD`): 고정 demo 3건 + `analyzed`에서 basic 제외 실기록을 대기 행으로 변환(분석 시각 포맷 `fd`, D-1/D-5/D-22). `cnt`(전체/만기/적중/빗나감/대기)와 필터·페이지네이션까지 여기서 계산. 적중률 카드 수치(일봉 61% 등)는 `ycTf`(L2496) 고정 더미.
- **분석 진행 연출**: `startRun` 스텝 난수(L2240 — sin 해시 결정식), `runCamV`(L2449~2458 — prog 기반 카메라 줌/팬 3단), `runDraw`(L2436~2447 — prog%6 순환으로 MA→볼린저→구름→채널→수평선→피보 순 작도, custom 32+에서 가중치 이동 미리보기), `ticks`(L2858~2867 — 32틱 그룹색), `progPct` 구간식(L2874~2878).
- **페르소나 레이더** (L2744~2780 `pHmField`): `heat` 5×3 집계 → 5축값을 16스포크로 보간 + sin 해시 노이즈 ±0.065 → 골드 폴리곤. 키 캐시(`_pfK`)로 재계산 억제.
- **파이/바 통계**: `pvPies`(L2546) 원호 dasharray 계산 외 수치는 전부 고정 더미. `peer`·`lvBoard`·`day14`·`styleFit`·`sigHours`·`engLearn`·`gSum`도 고정 배열(§3-3) — **파생 아님, 상수**.

## 6. 예상과 다른 것 / 지침·브리프와 어긋나는 것

1. **페르소나 질문은 15문**(L2704~2719) — 브리프의 "17문"과 불일치. 카피는 "500문 은행"(BANK=500, L2724·L1612)이라 실서비스 계약은 별도 확정 필요.
2. **"적중 환급 +1 스쿱"은 마크업 카피에만 있고(L321·L1199) 지급 코드가 없다** — 실개발 시 구현 여부를 결정해야 함.
3. **일일 한도 중 상당수가 비영속**: 종목 변경 6회(`stkOpN`)·종목 추가 XP 3회(`stkXpN`)·페르소나 5답(`pqDay`)·연속 방문(`strk7`)은 localStorage에 저장되지 않아 재시작하면 리셋 — "내일 초기화" 문구와 실동작 불일치. 진짜 일 단위로 유지되는 것은 `dVisit`(dv) 안의 것뿐(첫 방문·메뉴 방문·작도 3회·심화/커스텀 1회).
4. **레벨 계산이 xp에 +42 기저를 깔고 시작**(L2270~2271) — 신규 계정도 Lv.2(42≥40)에서 출발하는 셈. 의도(데모 연출)인지 실계약인지 확인 필요.
5. **XP 일일 총상한 없음** — 액션별 한도만 존재. `xpToday`는 표시용 집계.
6. 커스텀 가중치·체크(`wts`/`chk`)와 작도 토글(`indOff`)이 **영속 대상에서 빠져 있다** — "내 조합"을 파는 기능인데 저장이 안 됨(프로토 한계로 보이나 실개발 데이터 계약에서 반드시 짚을 것).
7. 리포트 본문 수치(합의 12/14·86%·목표 +6.2%·손절 174.20)는 T의 `tgt`와 무관한 **고정 카피**(L2658~2669) — 종목을 바꿔도 문장은 NVDA 기준.
