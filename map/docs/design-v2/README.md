## 1. 확정된 것 (시안이 뒤집을 수 있음 — 전제 7)

- **별도 모바일 개발 없음.** 앱은 `forge.html` + 스크립트 6종을 그대로 실행하고 세로 배치만 같은 파일에서 만든다.
- **골격**: 스티키 차트 3단 접힘 + 하단 세그먼트 4칸(근거 · 시점별 · 지표 · 판독문).
- **보드 13종 전량**이 결과 콘텐츠(오실레이터 7 + 파동 2는 S17).
- **샘플 7종**: NVDA · AAPL · MSFT · GOOGL · AMZN · BTC/USD · ETH/USD.
- **경제**: 기본 0(무제한) / 심화 2 / 커스텀 3 · 개설 지급 15 · 광고 +3 · 출석 1/6h · 상한 30.
- **스토리 축**: 첫 90초 → 첫 15스쿱 → 다음 날 아침 채점(S16) → 7일째 성적표.
- **디자인 감각**: 개방감 기본, 밀도는 작도 영역·심오한 분석 콘텐츠만. 조작은 탭 기본, 롱프레스 금지.
- **시안이 요건을 고친다**(전제 7) — “지침에 없다”로 시안을 거절하지 않는다. 협상 불가는 **정직 표기 · 법적 고지 · 엔진 단일 원본** 셋뿐.

## 3. 시안이 도착하면 — 인테이크 절차

```bash
cd ~/projects/vdiportal/map/docs/design-v2
unzip -O cp949 시안2.zip -d raw/        # 한글 파일명 대비. 안 되면 -O utf-8
find raw -type f | sort                  # 인벤토리
```

그 다음 순서대로:

1. **인벤토리** — 화면 몇 장인지, 형식이 무엇인지(HTML · 이미지 · Figma 내보내기 · PDF).
2. **대조표 작성** — 시안의 화면 ↔ `app-spec.html` 의 S0~S17. **어느 쪽에만 있는 것**을 양방향으로 뽑는다.
   - 시안에만 있음 → **새 기능 요건 후보**(전제 7 — 수용하고 문서를 고친다)
   - 요건에만 있음 → 시안 누락인지 의도적 제외인지 확인
3. **시각 규격 추출** — 여백 · 타이포 스케일 · 색 토큰 · 컴포넌트 치수. `design-kit.html` §2·§3 을 **시안의 실제 값으로 갱신**한다.
4. **세로 예산 재계산** — `design-kit.html` §7 은 추정치다. 시안의 실제 행 높이로 다시 계산해 갱신한다.
5. **접근성 재측정** — 시안이 새 팔레트를 주면 `design-kit.html` §8 의 대비비를 다시 잰다(현재 `--muted`·`--faint` 미달).
6. **충돌 판정** — 어긋나는 것이 나오면 **시안을 우선**하고 요건을 고친다.
   협상 불가는 셋뿐: **정직 표기 · 법적 고지 · 엔진 단일 원본**. 이 셋도 거절이 아니라 *의도를 지키며 불변을 유지할 방법*을 찾는다.
7. **문서 갱신 + 배포** — `app-spec.html` · `design-kit.html` 개정 이력에 한 줄, 커밋, cafe24 업로드, 아티팩트 재발행.

## 5. 1차 시안은 봉쇄됐다

1차 시안은 구현과 **함께 묶여** `_archive/mobile-2026-08-19/docs/design_handoff/` 로 들어갔다.
사용자 지시 2026-08-19 — *“오히려 혼란만 줄 것”*, *“시안2가 나왔을 때 온전히 거기에만 집중해야 한다”*.

- **1차와 2차를 나란히 두면 “어느 쪽을 따르나”가 생긴다.** 2차가 나오는 순간 그것이 유일한 시각 정본이다.
- 1차는 온보딩 7단계에만 반영됐고 리포트 화면군은 그 시안을 안 보고 지어졌다 — **대조 기준으로도 이미 무효**다.
- 시안과 구현을 따로 두면 **둘 중 하나는 반드시 참조된다.** 그래서 한 덩어리로 닫았다.

**비교표를 만들지 않는다. 2차 시안이 이 프로젝트의 유일한 시각 정본이다.**
