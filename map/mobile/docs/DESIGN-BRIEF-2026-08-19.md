# 머니스쿱 모바일 — 2차 시안용 요건 정의

> **이 문서는 디자인 시안을 다시 그릴 때 참고하는 요건서다.**
> 1차 브리프([`DESIGN-BRIEF.md`](DESIGN-BRIEF.md), 2026-08-15)는 "지금 있는 기능을 시안으로 옮기기 위한 분해도"였다.
> 이 문서는 다르다 — **1차 시안대로 구현해 본 뒤 드러난 문제와, 그 결과 확정된 제품 결정**을 담는다.
>
> 작성 2026-08-19 · 기준 커밋 `main`(P1b 병합 지점) · 결정 출처: 사용자와의 설계 논의

---

## 0. 이 문서가 생긴 이유

1차 시안대로 지은 것은 **온보딩 7단계뿐**이다. 리포트 화면군(무료·유료 분석)은 **시안을 보지 않고** 정보 설계서만 보고 지어졌고, 그 결과 개편 전 화면의 연장이 됐다. 그 실패의 규율화는 [`map/CLAUDE.md §④-2`](../../CLAUDE.md)에 있다.

그리고 더 큰 문제가 드러났다 — **시안에도 없던 것**이다.

> **"사용자가 설치 후 첫 방문부터 매일 들어와서, 계속 광고를 자발적으로 누르며 보상을 받고 싶은 심리가 있어야 하는데, 지금 화면엔 그런 느낌이 아예 없다."** (사용자, 2026-08-19)

이건 화면 스타일 문제가 아니라 **동기 설계** 문제다. 2차 시안은 이걸 풀어야 한다.

---

## 1. 확정된 것 — 제품 정체성

**바뀌지 않는다.** 32개 기술적 지표로 종목의 방향을 판정하고, 그 판정이 다음날 실제로 맞았는지 확인시켜 주는 앱. 재화(스쿱)로 더 깊은 분석을 사는 구조.

---

## 2. 확정된 것 — 사용자가 매일 오는 이유 (세 동력)

| | 동력 | 언제 |
|---|---|---|
| ① | **내 예측이 맞았는지 확인** | 아침, 어제 건 예측이 판정되는 순간 |
| ② | **오늘의 새 분석을 받으러** | 확인 직후, 다음 판을 시작 |
| ③ | **출석 보상(스쿱)** | 6시간마다 |

**셋이 하나의 고리로 닫힌다:**

```
연다 → ① 어제 예측이 판정된다 → ② 출석 보상을 받는다
     → ③ 그 스쿱으로 오늘 분석을 한다 → ④ 그 분석이 내일 판정될 예측을 만든다
     → 다시 ①
```

시안 문서가 말한 **"5번이 1번을 만든다"** 가 이것이다. **2차 시안은 이 고리가 감정적으로 어떻게 도는지를 그려야 한다.** 1차 시안은 고리를 그렸지만 각 지점에서 사용자가 무엇을 느껴야 하는지는 설계되지 않았다.

### ⑥시간 주기가 만드는 리듬 (새 결정)

출석을 **하루 1회가 아니라 6시간마다**로 바꾼다. 결과적으로 **하루 네 번 들어올 이유**가 생긴다 — 하루 한 번보다 강한 재방문 유도다.

두 리듬이 공존한다:
- **6시간 리듬** — 스쿱 수급
- **하루 리듬** — 예측 판정(어제 것이 오늘 결판)

아침 첫 방문에서 둘이 겹친다. **그 순간이 하루 중 가장 감정이 큰 지점**이므로 시안이 여기에 가장 공을 들여야 한다.

---

## 3. 확정된 것 — 경제

| 항목 | 값 | 지금 코드 | 비고 |
|---|---|---|---|
| 무료 분석 도구 | **5개** | 동일 | 기본분석. 종목 수·횟수 **무제한** |
| **Pro** (32도구) | **2스쿱** | `full: 3` | **인하 필요** |
| **Custom** (가중치) | **3스쿱** | `custom: 5` | **인하 필요** |
| 출석 보상 | **1개 / 6시간** (하루 최대 4) | `W_CHECKIN=1`, **하루 1회** | **주기 변경 필요** |
| 연속 출석 상자 | 7일마다 +5 | `W_CHEST=5`, `W_CHEST_EVERY=7` | 그대로 |
| 광고 1편 | **+3스쿱** | 확인 필요 | |
| 광고 하루 상한 | 8편 | `W_AD_DAILY=8` | 그대로(재검토 여지) |
| 잔량 상한 | **30** | `W_CAP=20` | **상향 필요** |
| 개설 지급 | 5 | `W_SEED=5` | 그대로 |

**하루 리듬 계산:**
```
출석만       4스쿱/일 = Pro 2회
광고 1편     +3      = Pro 1.5회분
상한 30              = Pro 15회 / Custom 10회
```

**하루 4개가 이 경제의 핵심 숫자다.** Pro 두 번이면 딱 떨어지고, **세 번째부터 광고를 봐야 한다** — 매일 그 순간이 온다. 막는 게 아니라 **더 하고 싶을 때 길이 있는** 구조다.

---

## 4. 확정된 것 — 무료와 유료의 경계

**지금 경계를 유지한다.** 무료도 방향·범위를 주고, 유료는 확신·근거·지평을 준다.

| | 무료 (5도구) | Pro (32도구) |
|---|---|---|
| 방향 | ✅ | ✅ |
| 범위 | ✅ | ✅ |
| 확신 퍼센트 | ❌ | ✅ |
| 세 지평 (내일·1주·1개월) | ❌ | ✅ |
| 반대 의견 | ❌ | ✅ |
| 적중률 · 기준선 | ❌ | ✅ |
| 32개 판독문 | ❌ | ✅ |

### ⚠️ 기각된 안 — **횟수 제한**

한때 "하루 무료 분석 N회" 같은 희소성 장치를 검토했으나 **기각**했다. 사용자 판정:

> **"분석을 많이 못하면 이탈해. 분석 과정을 보는 게 게임처럼 재미가 있는 건 아니잖아. 이건 가치있는 정보를 얻기 위함이 목적이야."**

**게임에서 희소성이 통하는 건 행위 자체가 재미이기 때문이다.** 여기서 분석은 **수단**이지 재미가 아니다. 정보를 못 얻으면 갈증이 생기는 게 아니라 **다른 서비스로 간다.**

**→ 2차 시안은 접근을 막아서 광고를 팔려 하면 안 된다. "더 깊이"로 팔아야 한다.**

## 5. 2차 시안이 풀어야 할 핵심 과제

### ① 유료의 값어치가 화면에서 느껴져야 한다

무료가 이미 **답(방향·범위)** 을 주므로, 유료가 "다른 답"이 아니라 **"같은 답의 부연"** 처럼 느껴진다. 실제로는 정보량이 크게 다른데 화면이 그걸 못 전한다.

**특히 주의할 실측 사실** — 심화가 무료보다 예측 **범위가 오히려 넓어지는 경우가 57.4%** 다(2,813창 실측, 폭 비율 중앙값 1.027). 정직하게 그렇게 표시하도록 구현돼 있으나, 사용자에겐 **"돈 냈는데 더 흐릿해졌네"** 로 읽힐 수 있다.

**시안은 이 사실을 감추지 말고 값어치로 바꿔야 한다.** 예: 넓어진 범위가 왜 더 정직한지, 무엇을 대신 얻었는지를 화면이 스스로 말하게.

### ② 유료는 **분석 과정이 재미있고 신뢰가 쌓여야** 한다 (사용자 요구)

> "유료는 분석 과정을 재미있게 보여주고 신뢰감도 얻을 수 있는 효과와 결과가 나와야 해."

**이미 있는 장치:**
- **19a 진행 중계** — 32개 지표를 **하나씩 실제로 읽는 과정**을 보여준다. 진행이 타이머가 아니라 **실제 엔진 호출 수**에 묶여 있다(빨리 끝나면 빨리 끝난다 — 늘리지 않는다). 현재 위치를 흰 막대로, 지난 것은 흐리게, 중간 집계(`상승 12 · 하락 4 · 횡보 1`)를 계속 보여준다
- **8b 해제 전환** — 방금 산 27개가 채워지는 장면. 3초 고정(보상 장면이므로 끝까지 재생), 동의·반대·무판정 세 통 + 카운터

**즉 "과정을 보여주는" 뼈대는 이미 있다.** 문제는 그것이 **재미와 신뢰로 느껴지게** 설계되지 않았다는 것 — 지금은 로딩 화면에 가깝다.

**2차 시안이 정할 것:** 이 두 장면이 어떤 감정을 만들어야 하는가. 기다림인가, 기대인가, 증명인가.

### ③ 광고가 통행료가 아니라 **선택**으로 느껴져야 한다

광고를 붙일 후보 지점(감정이 큰 순서):
- **어제 결과를 여는 순간** — 봉투 뜯기 직전
- **무료 판정을 본 직후** — "얼마나 믿을 만한지 보시겠어요?"
- **스쿱이 모자랄 때** — 지금 유일하게 구현된 자리
- **출석 보상 증폭** — "2배로 받기"

## 6. 이미 만들어져 있는 것 (2차 시안이 재사용할 수 있음)

**서버 원장** — 계정·잔량·출석(`streak_days` 포함)·광고 지급(`ad_grants`, AdMob SSV 검증)·환불·구글 계정 병합. 동시성 시험까지 있음.

**앱** — 3탭 셸·라우터·시트 · 워치리스트 · 무료/유료/전문 리포트 · **가중치 편집기**(0.1~3.0 연속 슬라이더, 30종) · 지갑 화면 · 결과·기록·스캔 화면 · 진행 중계(19a) · 해제 전환(8b) · **온보딩 7단계(1차 시안대로 재작성됨 — 참조 품질)**

**분석 엔진** — PC 스쿱포지와 **같은 엔진 공유**. 32지표, 백테스트 실측(31,971건·87시리즈).

## 8. 시안이 알아야 할 실측 사실

**1차 시안의 전제 중 실측으로 반증된 것이 있다.** 2차 시안은 이 수들을 근거로 그려야 한다.

| 사실 | 값 | 시안에 주는 의미 |
|---|---|---|
| 심화가 무료보다 범위가 **넓어짐** | **57.4%** (2,813창, 중앙값 1.027배) | *"심화는 범위를 절반으로 줄인다"* 는 1차 전제는 **거짓**. 화면이 "좁아진다"고 말하면 안 됨 |
| 방향 적중률 (상승 판정) | 61.7% | 기준선 **60.96%** 를 반드시 병기 |
| 방향 적중률 (하락 판정) | **42.5%** | 기준선보다 18.5%p **낮음**. 그대로 보여주는 것이 이 앱의 규율 |
| 티어별 적중률 | 기본 58.2% / 심화 58.5% | **거의 같다.** 심화의 값어치는 적중률이 아니라 **커버리지·보정**(73.8%→77.1%, ECE 4배 개선) |
| 「한 문장으로」 과열 절 | 23.5% 창에서 발생 | |
| 저항선 절 | 20.7% | |
| 둘 동시 | 1.3% | 두 절을 따로 둔 것이 정당 |
| 전문 프리셋별 지표 수 | 추세 9 · 모멘텀 6 · 거래량 30 · 변동성 9 · 구조 30 | **"32개"가 아니다.** 프리셋마다 다름 |
| 조절 가능한 지표 풀 | **30** (gann·pattern 제외) | 전문 시트가 "32"라고 하면 거짓 |
| 중립 판정 | 실제로 발생함 | 중립이면 반대 의견·적중률이 **정의되지 않음** — 값 대신 이유를 보여주도록 구현됨 |

## 9. 이 앱이 지키는 정직성 규율 (시안이 어기면 안 되는 것)

**리뷰 40여 회를 돌며 하나씩 찾아낸 것들이다.** 시각을 다시 그려도 이 규율은 유지된다.

- **방향 적중률에는 기준선(60.96%)을 반드시 병기한다** — 단독으로 놓으면 "동전보다 낫다"로 읽힌다
- **그 수치가 몇 개 도구로 잰 표본인지 밝힌다** — 적중률은 19지표 sampleGraph 기준이라 리포트의 32와 다르다
- **표본 20건 미만이면 퍼센트를 쓰지 않는다**
- **재보지 않은 것을 단정하지 않는다** — 두 값을 비교하는 문장은 매번 실제로 재고 말한다
- **못 그리는 것을 팔지 않는다 · 살 수 없는 것을 약속하지 않는다**
- **잔량을 낙관적으로 올리지 않는다** — 서버 확정 후에만
- **못 준 값은 받지 않는다** — 실패 시 환불, 모든 실패 사유에 다음 행동
- **막다른 골목 금지** — 막히는 상태 전부에 다음 행동 버튼
- **무엇이 빠졌는지 이름으로 적는다** — 숨기지 않는다(중립 카드·자백한 도구가 그 예)
- **항목 좌측 세로 컬러 라인 금지** (사용자 명시 금지)

## 11. 2차 시안에 바라는 것 (정리)

1. **세 동력의 고리**를 감정선으로 그릴 것 — 특히 아침 첫 방문(판정 + 출석이 겹치는 순간)
2. **유료의 값어치**가 한눈에 보이게 — 무료가 이미 답을 주는 상태에서
3. **분석 과정(19a·8b)** 이 로딩이 아니라 **재미와 증명**이 되게
4. **광고가 선택**으로 느껴지는 자리와 문구
5. **넓어지는 범위**를 값어치로 바꾸는 표현
