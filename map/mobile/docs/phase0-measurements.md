### 봉 수 의존성 (핵심)

실행시간은 봉 수에 **강하게** 의존하며 초선형이다(데스크톱 실측, 약 O(n^1.5)).

| 봉 수 | 데스크톱 | µs/봉 |
|---:|---:|---:|
| 549 | 66.7ms | 121.5 |
| 1000 | 136.1ms | 136.1 |
| 2383 | 545.2ms | 228.8 |
| 3500 | 1005.7ms | 287.3 |
| 5031 | 1990.4ms | 395.6 |

폰 실측도 같은 형태다: 549봉 20.8ms → 5031봉 809.5ms (**28배**).

## 판정

- **Web Worker 도입: 조건부 불필요.**
  근거: 플래그십 실기기에서 반복 실행 1074ms < 2000ms. 다만 폴드7은 플래그십이고, 중급기는 단일 스레드 JS 가
  통상 2~3배 느리다 → 같은 봉 수면 2.2~3.2초로 **임계를 넘는다**.
  **전제: 일봉 히스토리를 줄일 것.** 1day 5031봉이 합계의 75%(810ms)를 차지하고 초선형이라, 1200봉 수준으로 줄이면
  폰 기준 약 55ms, 3주기 합계 약 320ms 가 되어 중급기 2.5배를 곱해도 0.8초로 여유롭다.
- **지표별 진행률 UI: 위 전제가 지켜지면 불필요.** 20년치를 그대로 넣기로 하면 Worker 와 함께 필요해진다.
- **Phase 1 이 답할 질문은 "Worker 를 넣을까"가 아니라 "각 주기에 몇 봉을 넣을 때 정확도가 꺾이는가"다.**
  백테스트로 실측 가능한 질문이다.

## 기기·환경

  — `Android 10; K` 는 **Chrome 이 개인정보 보호로 축약한 고정 문자열**이며 실제 OS 버전이 아니다. 오독 주의.
- 커버 화면 411×814 CSS px · DPR 2.625 (실 픽셀 약 1079×2137)
- 펼친 화면: 미측정
- 반복 실행 시 **분석이 38% 느려졌다**(네트워크는 오히려 4배 빨라진 상태에서). 발열 스로틀 또는 CPU 거버너로 추정.
  지속 사용 시 성능은 콜드 측정보다 나쁘다 — 여유를 콜드값으로 잡지 말 것.
- 두 회차의 verdict 가 완전히 동일(점수 0 · 목표 329.48 · 무효화 306.11 · 합류 56 (15/27)) — 기기에서도 결정론적.

## 부수 확인

- **`forge-tools.js` 이벤트**: pointer 7건 / mouse 0건 / touch 0건. **Pointer Events 전용이라 터치 재바인딩 불필요** —
  포인터 이벤트가 마우스·터치·펜을 통합한다. 단, 드로잉 도구를 실제로 붙일 때 캔버스에 `touch-action: none` 이
  필요하다(없으면 브라우저가 제스처를 스크롤로 가로챈다).
- **실거래량이 엔진에 도달한다**: 세 주기 모두 `거래량 실측` 표시. 최종 리뷰에서 고친 `MSGraph.setVolume` 배선이
  실기기에서 동작함을 확인.
- **cafe24 PHP 의 SQLite(PDO) 확장 유무**: 확인하지 않음. Phase 0 완료에 불필요하고, 확인하려면 서버에 임시 프로브를
  올렸다 지워야 해 별도 승인이 필요하다. **v2 지갑 계획 시점 항목**으로 이관.

## 오정정 — 초기 계획서가 틀렸던 것

계획서 §선행 조사에 **"실행시간은 봉 수와 무관하게 일정(~50ms). 5000봉 ≈ 600봉"**을 사실로 적었다. **틀렸다.**

원인: `ForgeCore.makeDemoSeries(n)` 이 **인자 `n` 을 무시하고 항상 480봉을 반환한다.** 600·1200·2500·5000 을 넣어 잰다고
믿으며 같은 480봉을 네 번 잰 것이다. 이 오류가 "데스크톱 32지표×3TF = 202.8ms" 와 "6배 스로틀 1.22초" 추정을 함께 오염시켰다.

두 오류가 서로 상쇄돼 결론(Worker 불필요)은 우연히 살았지만, 경로는 전부 틀렸다.
**교훈: 합성 데이터 생성기의 출력 크기를 단언 없이 믿지 말 것.** 이 랩의 측정 스크립트는 앞으로 `price.length` 를 먼저 찍는다.

## Phase 1 로 넘기는 것

1. **봉 수 ↔ 정확도 실측** — 주기별 최적 히스토리 길이. Worker 회피의 전제이자 이번 측정의 가장 큰 산출물.
2. **Capacitor 툴체인 검증** — `cap add android` 까지 완료(커밋 44285fc)했으나 Gradle 빌드·APK 설치·WebView 실행은 미검증.
   GUI 있는 자리에서 Android Studio 로 `map/mobile/android` 를 열어 폴드7에 Run.
3. **폴드 펼침 전환** — `configChanges` 5토큰이 매니페스트에 존재함은 정적 확인. 실제 액티비티 유지 여부는 APK 로 확인 필요.
4. **`android:allowBackup="true"`** — 템플릿 기본값. v2 에서 인증·지갑 상태가 들어오기 전에 끌 것.
5. **`package-lock.json` 카브아웃** — 저장소 루트가 전역 제외. `map/mobile` 은 첫 실 npm 의존성 트리이고 해석 버전이
   생성 `android/` 템플릿 내용을 좌우하므로 `!map/mobile/package-lock.json` 예외 권고.
6. **`?since=` 증분 시세** — 콜드 수신 942ms. Phase 1 은 증분 경로를 쓸 것.
7. **재사용되는 것** — `api.js`·`graph.js`·`chart.js`·`bench.js` 와 40개 테스트. 버려지는 것은 `index.html`·`style.css`·`spike.js`.
