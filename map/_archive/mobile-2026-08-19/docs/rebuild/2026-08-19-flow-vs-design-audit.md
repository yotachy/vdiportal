**범위**: 사용자 동선·화면 간 이동·결정 지점·되돌아가는 길. 시각(색·타이포·여백)은 다루지 않는다 —
그건 같은 날 앞서 돈 [`2026-08-19-report-vs-design-audit.md`](2026-08-19-report-vs-design-audit.md)(이하

변경 없음. 스크린샷 5장의 수정은 이 감사가 시작되기 전, 동시에 도는 다른 작업이 만든 것이다).

## 1. 시안이 설계한 동선 (원문 그대로, 해석 없음)

동선 문서는 21턴에 걸쳐 자기 이전 결정을 여러 번 뒤집는다. 아래는 **최종본**(README.md 의 요약표 +
턴 17·19·20·21 의 최신 결정) 기준이다 — 중간 턴(1~16)의 폐기된 안은 "버려진 것"으로만 인용한다.

### 세 갈래 여정 (여정 문서 원문)

```
첫 실행 → 온보딩 6단계 › 워치리스트 › 기본분석 리포트  (스쿱 10 · 종목 3 · 성향 1을 들고 나옴)
재방문   → 워치리스트 › 기본분석 › 해제 유도 › 심화분석  (온보딩은 건너뜀)
획득     → (막힌 순간 · 리포트 직후 · 출석 직후) › 광고 › 적립하는 중 › 원래 하려던 분석으로 복귀
다음날   → 알림(어제 결과) › 워치리스트 상단 결과 카드 › 결과 상세 › 반대 지표를 올려 전문분석
```

(여정 문서는 "6단계"라 적었으나 이는 초기 턴 값 — README 는 이후 **7단계**로 확정한다. 아래 표는
README 기준.)

### A. 첫 실행 — 7단계(README 확정본, 턴 17 최종)

| # | 화면 | 게이트 |
|---|---|---|
| 1 | 콜드 오픈 — 직접 찍기 | — |
| 2 | 투자성향 — 4종 중 1 | 필수 |
| 3 | 위험 고지 | 체크 필수 |
| 4 | 종목 1개 + 기본분석 체험(무료) | — |
| 5 | 심화분석 체험 — 폭이 절반 | — |
| 6 | 전문분석 체험 — 슬라이더 1개(Trend) | — |
| 7 | 완료 · 가격표 · 스쿱 10 | → 워치리스트 |

**가격은 값을 다 겪은 뒤(7단계)에만 공개된다** — 턴 15 의 핵심 결정. 턴 16(3모드 체험 튜토리얼)이
4~6단계를 채우고, 턴 17 이 이 순서를 정본으로 확정하며 이전 턴들(2/6 원리 시연·3/6 가격표 선공개·
5/6 종목 3개)을 명시적으로 폐기한다.

### B. 매일 루프 (턴 14·17·19 최종)

```
알림(어제 예측 3건 결과) → 워치리스트(결과 카드 최상단 + 스캔이 찾은 뒤집힘)
  → 결과 상세 → 오늘 판정(기본) → 27개 잠김 → 해제(광고/스쿱) → 심화분석
  → 내일 확인할 결과가 하나 더 예약됨 ↺
```

**"5번이 1번을 만든다"**(README 원문) — 심화분석을 볼 때마다 내일 확인할 결과가 생기고, 그 결과가
다음 날 앱을 열게 한다. 이 고리가 없으면 광고 노출 횟수 자체가 늘지 않는다는 것이 턴 14 의 핵심
주장이다.

결과 상세는 **적중/오답에 따라 다음 행동이 갈린다**(비대칭이 이 화면의 전부, 턴 14b/17b):
- 맞은 날 → 광고 권유(진입점 4). "오늘도 심화로 보기"
- 빗나간 날 → **광고를 권하지 않는다.** 대신 "기본분석이었다면 적중이었습니다"를 먼저 말하고,
  "반대했던 6개 중 4개가 맞았다 — 올려서 다시 볼까요?"로 **전문분석**을 제안한다.

### C. 광고 진입점 6곳(턴 17, 3곳에서 확장)

| # | 트리거 | 형태 |
|---|---|---|
| 1 | 막힌 순간 | 시트 안에서 바로 전환(지갑으로 안 보냄) |
| 2 | 리포트 다 읽은 뒤 | 잔량 3 미만일 때만 |
| 3 | 출석 직후 | 같은 덩어리에 "하나 더 받기" 이어붙음 |
| 4 | 맞힌 결과 확인 직후 | 빗나간 날엔 절대 안 뜸 |
| 5 | 스캔이 뒤집힘을 찾은 직후 | "2개 뒤집힘 · 둘 다 심화면 6스쿱"으로 **부족분을 스스로 계산하게** 함 |
| 6 | 연속 출석이 끊기기 직전 | "6일 연속 · 내일이면 상자" |

한 세션 광고 권유 **최대 2회**, 거절하면 그 세션엔 다시 안 묻는다(원칙 7).

### D. 공용 시트 2개(턴 12) + 단계 선택 시트(턴 6b)

- **단계 선택 시트**(6b) — 리포트의 해제 블록에서 옴. 3색(기본/심화/전문).
- **종목 추가 시트**(12a) — 들어오는 길: 워치리스트 하단 · 빈 목록. **칩 그리드가 검색창보다
  위**(처음 쓰는 사람은 티커를 모른다). 이미 담은 종목은 지우지 않고 **잠근다**.
- **성향 변경 시트**(12b) — 들어오는 길: **리포트 헤더의 성향 칩**. 바꾸면 무엇이 남고(이미 산
  심화·전문 결과) 무엇이 다시 드는지(새 성향 기본분석 재계산 무료 · 심화 재구매 3스쿱)를 버튼 위에
  직접 적는다 — "감추면 신뢰를, 적으면 사용을 얻는다".

### E. 전문분석 편집기(10a) — 독립 화면

"전용 편집 화면(**뒤로가기 있는 풀스크린**)"으로 명시적으로 그려졌다(턴 10·9c 주석). 들어오는 길은
둘: 단계 선택 시트의 "전문분석" 행 · 심화분석 결과의 "전문분석으로 올리기"(턴 14b, 반대 지표 근거
기반). 시트("얼마나 정밀하게")와 편집기("어떤 지표를 얼마나")는 **다른 질문**이라 다른 화면이라는
것이 명시적 근거다.

### F. 재열람(21a) — 턴 21 최종 결정

이미 산 결과를 다시 열면:
1. **"어제 09:41 에 받은 결과입니다"** 시점 배너 + "그 뒤로 봉 1개가 더 생겼습니다"
2. 판정 카드는 **투명도를 낮춰** 흐리게(오늘 값과 착각 방지 — "이 화면에서 가장 위험한 오해")
3. "오늘 기준으로 다시 보시겠어요?" → 3스쿱으로 재분석. **재열람 자체는 무료.**

### G. 나머지 개별 화면(README 표에서)

판독문 32개(20a, 지표당 3줄 고정) · 내 예측 기록(20b, "빗나간 N건" 필터가 기본 탭 옆 · 20건 전엔
퍼센트 없음) · 알림 권한(20c, **첫 심화분석 직후에만** 묻는다 — "안 보내는 것"도 목록에 적음) ·
적립하는 중(11d, 낙관적 가산 금지) · 스캔 결과(15c, 뒤집힌 종목만 · 왜는 말하지 않음) · 막히는
상태 7종(12c, 전부 다음 행동 포함).

## 2. 현재 앱의 실제 동선 (코드로 확인)

### 라우터 구조

3탭 독립 스택(`router.js`) — `list`(워치리스트) · `analysis`(리포트) · `scoop`(지갑). 이건 시안의
3탭 셸(턴 1)과 **정확히 일치**한다. `go()`가 같은 화면으로 재진입 시 되감기까지 한다(리뷰 I1) — 구조
자체는 튼튼하다.

**등록된 라우트 6개뿐**: `watchlist · report · wallet · record · result · scanresult`.
**판독문(20a)과 전문분석 편집기(10a)는 라우터에 없다** — `app.js` 자체 주석이 이유를 밝힌다: 리포트가
계산한 데이터를 넘겨받아야만 그려지므로 독립 라우트로 못 들어간다.

```
watchlist ──tap row──────────────► report ──"판독문 N개"─► (readings-list, root.innerHTML 직접 교체)
    │                                 │
    │──pill/스캔──► wallet            │──"전문분석으로"─► (MSExpert.open, .xp-scrim 오버레이)
    │──결과카드──► result             │──pill──► wallet
    │──더보기────► record             │
    │──뒤집힘 있으면──► scanresult    │
    │                                 │
result ──"오늘도 심화로"/"전문 시도"─► report
scanresult ──카드/버튼──► report
record ──(코드 확인: 없음, 뒤로만)
```

### 실제로 없는 접점

- **성향 변경 시트**: 리포트 헤더 성향 칩은 **표시만** 한다. `report.js:710` 주석: "탭 동작(성향
  변경 시트)은 P2 — 지금은 표시만 한다." `strings.js:286`: "탭하면 성향 변경 시트(12b)가 열려야
  하지만 그건 P2 다." **`sheet.js`는 12b 를 자기 소비자 목록에 이미 적어 두었는데(주석), 실제
  소비자는 코드베이스 어디에도 없다** — `grep -rn "성향 변경"` 은 주석 4건만 반환하고 실행 코드
  0건이다.
- **알림 권한(20c) / 알림 발송**: 코드베이스 전체에서 "알림"·"notification"·"권한" 이 등장하는
  파일은 셋뿐이고, 전부 **주석**이다 — `shell.js`(지갑 탭 배지가 "P1~P3 가 알림원을 만들면서... 그때
  실제로 호출하기 시작한다"는 미배선 선언) · `result.js`(설계 인용 주석) · `scan-result.js`(설계
  인용 주석). **실행되는 알림 권한 요청도, 알림 발송 로직도 하나도 없다.**
- **재열람 흐림 처리**: `report.js:1807` — `if (bought) { data=bought.data; an=bought.an;
  state="ready"; draw(); }`. 시점 배너·투명도·"오늘 기준 다시보기" 버튼 어느 것도 없다. 이미 산
  결과를 다시 열면 **오늘 새로 분석한 것과 화면이 동일하다.**

## 3. 대조 — 어긋남 목록

### 3.1 동선 결손 (시안이 의도한 흐름이 성립하지 않음) — 6건

**① 하드웨어 뒤로가기가 판독문(20a)·전문분석 편집기(10a)를 모른다**

`shell.js` 의 `handleBack()`은 딱 두 가지만 안다 — `MSSheet.closeTop()`(등록된 시트를 닫는다) 아니면
`router.back()`(탭 스택을 물린다). `MSReadingsList.render()`는 `root.innerHTML`을 직접 갈아치우는
방식이라 라우터에도 `MSSheet`에도 존재를 알리지 않고, `MSExpert.open()`은 `document.body`에 자기
`.xp-scrim`(고정 오버레이, 배경 덤·`max-height:92dvh` 시트)을 직접 붙이는데 이 역시 `MSSheet`
스택에 안 올라간다(`grep` 확인 — `xp-scrim`을 참조하는 곳은 `expert.js`·`style-expert.css` 뿐).

**사용자에게 뜻하는 것**: 판독문 32개를 열어 놓고 하드웨어/제스처 뒤로가기를 누르면, 화면이 리포트로
안 돌아가고 **탭이 통째로 워치리스트로 튄다**(router.js `back()`: 스택 길이 1일 때
`tab = HOME`("list")). 방금 읽던 리포트는 사라진 것처럼 보인다. 전문분석 편집기는 더 나쁘다 —
`closeTop()`이 아무것도 못 찾고 `router.back()`이 그대로 실행되어 **밑에 깔린 화면이 탭째 바뀌는
동안 편집기 오버레이는 화면에 그대로 남는다** — 잘못된 화면 위에 뜬 반투명 모달이라는, 사용자가
설명할 수 없는 상태가 된다. 이건 시안의 "막다른 골목을 만들지 않는다"(원칙 6) 와 결이 같은
문제다 — 골목이 막힌 게 아니라 **엉뚱한 곳으로 순간이동**한다.

**② 성향 변경 시트(12b)가 존재하지 않는다**

시안이 "공용 시트 2개"라고 부른 것 중 하나가 없다. 성향을 바꾸고 싶은 사용자는 **방법이 없다** —
리포트 헤더 칩은 눌리지 않는다. 온보딩에서 고른 성향은 앱을 다시 설치하기 전까진 영구히 고정된다.

**사용자에게 뜻하는 것**: "나중에 바꿀 수 있습니다"(온보딩 4단계 문구)라는 약속이 지켜지지 않는다.
성향을 잘못 고르거나 마음이 바뀐 사용자는 앱의 판정 전체가 자기 기준과 안 맞다고 느껴도 고칠 방법이
없다 — 이건 사소한 기능 하나가 아니라 "성향이 판정을 좌우한다"는 앱의 핵심 전제(턴 4)를 사용자가
검증·조정할 유일한 통로가 막힌 것이다.

**③ 알림 권한 화면(20c)과 알림 발송 메커니즘이 전무하다**

매일 루프의 **시작점**("알림 → 워치리스트")이 코드에 없다. 지갑 탭 배지는 이 알림원이 생기면
쓰겠다는 미배선 훅으로만 존재한다.

**사용자에게 뜻하는 것**: 시안은 이 알림을 "약속한 답을 주는 알림이라 정당하다"고 설계했고, README
는 이게 광고 노출 총량을 좌우하는 **가장 상위의 지렛대**라고 명시한다("5번이 1번을 만든다"). 지금은
사용자가 **스스로 기억해서 앱을 다시 열어야만** 어제 결과를 본다 — 능동적 재방문 유도가 수동적
발견으로 완전히 대체됐다. 워치리스트 상단 결과 카드(있음, §3.2 참고)는 이 고리의 절반만 채운다.

**④ 재열람(21a)에 낡음 표시가 없다**

이미 구매한 심화·전문 결과를 다시 열면, 오늘 새로 계산한 것과 화면상 구분이 안 된다. 시점 배너도,
흐림 처리도, "오늘 기준 다시보기" 유도도 없다.

**사용자에게 뜻하는 것**: 정확히 시안이 "이 화면에서 가장 위험한 오해"라고 부른 상황이 실제로
일어난다 — 어제 산 234.2 ± 1.1 이라는 값을, 봉이 하루 더 쌓인 오늘도 여전히 유효한 판정으로 오인할
수 있다. 예측 결과를 파는 제품에서 "이게 언제 값인지"가 불분명한 것은 신뢰 문제다.

**⑤ 광고 진입점 5(스캔 뒤집힘 직후)의 핵심 장치가 없다**

`scan-result.js`는 "무엇이 달라졌는지"까지는 정확히 시안대로 그린다(경계 원칙까지 주석에 옮겨
적었다). 하지만 시안이 이 진입점의 **엔진**이라고 부른 문장 — "2개가 뒤집혔습니다 · 둘 다 심화로
보면 6스쿱" — 은 어디에도 없다(`strings.js` srSubA/srSubB/srBoundary 어느 키에도 스쿱 비용 계산이
없다). 지금은 그냥 "테슬라부터 보기" 버튼으로 리포트에 보낼 뿐이다.

**사용자에게 뜻하는 것**: 시안의 의도는 사용자가 버튼을 누르기 **전에** "이게 얼마짜리 확인인지"를
스스로 계산하게 해 광고 시청 동기를 만드는 것이었다. 지금은 그 계산을 사용자가 할 재료 자체가
없다 — 그냥 리포트로 이동해서 평소와 같은 해제 블록을 만날 뿐, 이 진입점이 다른 진입점과 구별되는
지점이 사라졌다.

**⑥ 광고 진입점 6(연속 출석이 끊기기 직전)이 능동적으로 작동하지 않는다**

`wallet.js`에 스트릭 도트·"N일 연속 · 7일 되면 +5" 표시는 있다(`walStreakNote`). 하지만 이건 **지갑
탭을 스스로 찾아 들어간 사람에게만** 보이는 수동 정보다. 시안이 말한 "끊기기 직전"이라는 타이밍
포착 — 출석을 안 한 채 하루가 저물어갈 때 먼저 말을 거는 것 — 은 §의 알림 메커니즘(위 ③)이 없어서
애초에 발동할 자리가 없다.

**사용자에게 뜻하는 것**: 스트릭이 끊기기 직전이라는 정보가 존재해도, 그 정보를 보려면 사용자가
이미 지갑 탭을 열어야 한다 — 즉 "놓칠 뻔한 사람을 붙잡는" 안전망이 아니라 "이미 안 놓친 사람에게
보여주는 현황판"으로 기능이 축소돼 있다.

### 3.2 자리 어긋남 (되긴 되는데 시안과 다른 곳에서 일어남) — 2건

**⑦ 전문분석 편집기(10a) — 독립 화면 대신 모달 오버레이**

시안: "뒤로가기 있는 풀스크린 화면". 현재: `MSExpert.open()`이 `document.body`에 `.xp-scrim`(배경
덤 처리) + `.xp-sheet`(`max-height:92dvh`)를 직접 붙이는 **바텀시트형 모달**. 내용(기준 성향 세그·
지표별 슬라이더 2줄 레이아웃·값 병기)은 시안과 거의 일치하지만, **틀(chrome)이 다르다** — 뒤로가기
버튼이 없고(닫기는 스크림 바깥 탭 또는 실행/재설정 버튼으로만), 하드웨어 뒤로가기도 못 닫는다(§3.1
①). 시각 감사는 이걸 "`.rp-weights` 인라인 카드"로 짚었는데, 정확히는 그 카드는 구매 후 요약
행일 뿐이고 실제 편집기는 이 모달이다 — 다만 결론(구조가 시안과 다르다)은 같다.

**사용자에게 뜻하는 것**: 5스쿱을 쓰는 결정을 내리는 화면이 "진짜 화면"이 아니라 "떠 있는 것"처럼
느껴진다. 뒤로가기가 안 먹히는 것(§3.1①)까지 겹치면 이 화면에서 나가는 유일하게 안전한 길은 실행
또는 재설정 버튼뿐이라, 탐색적으로 만져보다가 그만두고 싶은 사용자가 쉽게 막힌다.

**⑧ 광고 진입점 4(맞힌 결과 직후) — "그 자리에서 바로"가 아니라 리포트로 우회**

시안 원칙 1: "그 자리에서 바로. 지갑으로 보내지 않고 선택한 티어를 위에 남긴다." 진입점 1(막힌
순간)은 실제로 시트 안에서 광고를 바로 튼다. 하지만 진입점 4(`result.js`)의 "오늘도 심화로 보기"
버튼은 `MSApp.go("report", {sym})`만 하고 끝난다 — 광고 자체는 리포트에 도착해 해제 블록을 다시
눌러야 시작된다.

**사용자에게 뜻하는 것**: 큰 문제는 아니다(탭 한 번 추가) — 다만 시안이 "기분이 가장 좋은 순간"이라고
부른 그 즉시성이 한 스텝 희석된다. 어제 결과가 맞았다는 걸 막 확인한 사람이 리포트 화면으로 옮겨가
스크롤을 더 하고서야 광고를 만난다.

### 3.3 군더더기 (시안이 없앤 것을 현재가 갖고 있음) — 1건 (+참고 1건)

**⑨ 워치리스트 상단 검색창 + 필터 칩**

동선 초기 턴(2a·3a·4d·5a)엔 "Search ticker or company"/"종목 검색" 입력과 전체·미국·한국·ETF 칩이
목록 화면 상단에 있었다. **최종본(턴 14a, README 화면표)엔 이 둘이 없다** — 검색은 종목 추가
시트(12a)의 칩 그리드 안으로 흡수됐고("검색창보다 칩 그리드가 위"라는 문장 자체가 시트 안의 얘기다),
목록 화면은 결과 카드 + 행 목록 + "종목 추가" 버튼뿐이다. 현재 `watchlist.js`엔 `.wl-search` +
필터 칩이 그대로 남아 있다(시각 감사가 이미 지적).

**사용자에게 뜻하는 것**: 기능 자체는 유용하지만, 시안이 이걸 뺀 이유는 "슬롯 있는 종목 목록"이라는
개념(온보딩에서 받은 슬롯 4개, 채우면 잠기는 자물쇠)을 지키기 위해서였다 — 검색으로 아무 종목이나
훑을 수 있으면 "내 워치리스트는 한정된 자리"라는 감각이 흐려진다. 순수 UX 관점에서는 "빠진 기능"이
아니라 "시안이 의도적으로 정리한 것을 다시 들여온 것"이다.

**참고 — 온보딩 2단계는 시안의 확정 결정을 초과한다(결함 아님)**

`onboarding.js` 헤더 주석이 스스로 밝히듯, 현재 7단계는 동선 문서 턴 16·17 을 그대로 옮긴 게
아니라 **별도의, 사용자 승인을 받은 재설계 문서**(`docs/superpowers/specs/
2026-08-18-moneyscoop-onboarding-redesign.md`, 2026-08-18)를 따른다. 그 문서의 O5 결정("시안은
상한이 아니라 하한 — 더 좋게 해도 된다")이 근거다. 결과적으로 턴 17 이 명시적으로 버린 "원리
시연"과 개념적으로 유사한 화면(2단계, "같은 구간 32개 전부 보기")이 다른 이유로 재도입됐고, 턴
16c(전문분석 체험 슬라이더)와 턴 17a(3티어 비교표)는 온보딩 재설계 문서가 **의도적으로 삭제**했다고
스스로 적어 뒀다(`state.r3`·`bandRow()` 삭제 커밋 로그). 이 프롬프트가 "온보딩은 시안대로 재작성
완료"라고 전제한 것은 **부정확하다** — 정확히는 "동선 문서의 턴 11 만 그대로 쓰고, 나머지는 더
나중에 나온 상위 재설계 문서를 따른다"이다. 사용자 승인이 있는 이탈이라 결함으로 세지 않지만,
동선 문서 자체를 개발 기준으로 삼으려는 사람은 이 사실을 모르면 온보딩 2·6·7단계에서 시안과 코드가
왜 다른지 설명할 수 없다.

## 5. 시각 감사 결론을 수정해야 하는가

**수정해야 한다 — "정보 구조는 유지 가능, 대부분 CSS"는 시각 감사가 스스로 정한 범위(리포트 화면군,
P1a·P1b) 안에서는 여전히 맞지만, 그 범위 밖(동선 전체)까지 포함하면 그 결론을 총론으로 쓸 수
없다.**

시각 감사가 이미 두 항목에서 구조 문제를 감지했다("구조까지 손대야 하는 곳은 둘: 전문분석 편집기
독립화면화, 워치리스트 검색창 제거") — 이 감사는 그 두 항목을 그대로 확인했고(§3.2⑦, §3.3⑨),
거기에 시각 감사의 스크린샷 대조 방식으로는 **원리적으로 볼 수 없는** 네 가지를 더 찾았다(§3.1
①②③④ — 하드웨어 뒤로가기 배선, 존재하지 않는 시트, 존재하지 않는 알림 메커니즘, 재열람 로직).
이 넷은 화면을 스크린샷으로 나란히 놓아서는 안 보인다 — 코드의 이벤트 배선과 라우팅 그래프를 읽어야
만 보인다.

**재작업 규모 판정**: 세 층이 섞여 있다.
1. **CSS 수준** — 시각 감사 §4 의 1·2·4·5번(카드 반경·타이포·워치리스트 카드 색·버튼 필형). 이
   부분은 시각 감사 결론이 그대로 유효하다.
2. **화면 단위 재배치** — §3.2⑦(전문분석 편집기를 모달에서 라우팅 화면으로 승격) · §3.3⑨(워치리스트
   상단 정리). 기존 컴포넌트를 다른 그릇으로 옮기는 수준.
3. **새 기능/배선** — §3.1②③④⑤(성향 변경 시트 신설·알림 인프라·재열람 로직·스캔 화면 카피)와
   ①(뒤로가기 배선). 이 중 ①은 코드 몇 줄(readings-list·expert 를 `MSSheet` 또는 라우터 화면으로
   편입)이라 저렴하지만, ③(알림)은 네이티브 권한 요청 + 로컬/푸시 스케줄링 + (설계가 요구하는) 서버
   쪽 "결과 확정" 신호까지 필요해 이 감사 대상 중 가장 크다.

즉 "대부분 CSS"가 아니라 **"시각 감사가 본 것은 대부분 CSS, 이 감사가 본 것은 대부분 배선과 신규
기능"** 이 더 정확한 총평이다. 둘은 같은 작업 목록 위에서 서로 다른 층을 가리키고 있어 충돌하지
않는다 — 다만 시각 감사의 결론만 읽고 "이번 재작업은 CSS 손질이면 끝난다"고 판단하면 §3.1 의 6건이
전부 계획에서 빠진다.

## 6. 재작업 순서 제안 (임팩트 순 상위 5개)

1. **뒤로가기 배선 수정** (§3.1①) — `MSReadingsList`·`MSExpert`를 `MSSheet.open()` 패턴으로
   편입(둘 다 이미 시트/모달 형태라 껍데기만 바꾸면 된다). 비용이 가장 작고, 유료 사용자 전원이
   매번 마주치는 혼란을 즉시 없앤다.
2. **재열람 낡음 표시** (§3.1④) — `report.js:1807` 의 `bought` 분기에 시점 배너 + 흐림 CSS +
   "오늘 기준 다시보기" 버튼 추가. 비용 작음, 신뢰 리스크(가장 위험한 오해) 제거.
3. **스캔 결과 비용 프레이밍 문구** (§3.1⑤) — `scan-result.js`/`strings.js`에 "N개 뒤집힘 · 전부
   심화로 보면 M스쿱" 한 줄과 계산 로직만 추가. 비용 매우 작음, 광고 진입점 5를 실제로 살린다.
4. **성향 변경 시트 신설** (§3.1②) — `tier-sheet.js`가 이미 같은 `MSSheet` 패턴의 첫 소비자라
   참고할 골격이 있다. "무엇이 남고 무엇이 다시 드는지" 문구는 동선 문서 12b 에 이미 확정돼 있어
   카피 작업도 끝나 있다. 중간 비용, 온보딩이 약속한 "나중에 바꿀 수 있다"를 실제로 지킨다.
5. **알림 권한(20c) + 발송 인프라** (§3.1③) — 비용이 가장 크다(네이티브 권한 + 스케줄링 + 서버
   신호). 그러나 설계가 명시한 **가장 상위의 지렛대**("5번이 1번을 만든다")라, 위 넷을 다 고쳐도
   이게 없으면 매일 루프의 출발점 자체가 계속 "사용자가 기억해서 열어야 발견"으로 남는다. 규모상
   별도 계획서로 쪼개는 편이 안전하다.

(6순위 후보: 전문분석 편집기를 독립 라우팅 화면으로 승격 — 시각 감사도 "구조 변경" 필요를 이미
