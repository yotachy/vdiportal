프로젝트: **머니스쿱 앱 개편** — 재시작 근거 문서.

## 0. 대조 방법 (재현 절차)

APK 내부 `assets/public/` 를 풀어 `mobile/www/` 와 비교한 결과 **cordova 심 2개(`cordova.js`·`cordova_plugins.js`)를 뺀 나머지가 완전히 동일**하다. 따라서 소스로 찍은 화면 = APK 화면이다.

```bash
# ① 앱 화면 — 상태를 씨앗으로 심고 7화면
bash mobile/tools/shots.sh <out>            # 지갑 응답이 필요한 화면은 POST mock 필요
# ② 시안 화면 — 아트보드를 낱장 HTML 로 뽑아 렌더
python3 mobile/tools/spec-shot.py <out> 14a 18a 18b ...
```

증거 이미지: `mobile/docs/rebuild/shots/` (`app-*.png` = APK, `spec-*.png` = 시안).

⚠️ 대조 중 **포트 8932 를 전날 세션의 좀비 서버가 점유**하고 있어 새 mock 이 한 번도 뜨지 않았다. 헤드리스 검증 전에 `ss -lntp | grep 8932` 로 확인할 것 — 조용히 옛 결과를 보게 된다.

## 1. 치명 결함 — 리포트 화면이 APK 에서 **항상** 죽는다

```
[report] load failed: MSPreds.seed is not a function
```

원인은 **전역 이름 충돌**이다.

| 파일 | index.html 로드 순서 | 등록하는 전역 |
|---|---|---|
| `draw-preds.js` | 35 | `root.MSPreds` = 예측선 **작도** API (`seed`·`wiggle`·`strokeLine`·`pcal`·`endDeco`·`confSeq`) |
| `predictions.js` | 43 | `root.MSPreds` = 예측 **기록·판정** API (`make`·`judge`·`pending`·`hitRate`) |

`chart-draw.js`(47) 는 로드 시점에 `factory(root.MSPreds)` 로 전역을 **캡처**한다. 그 시점의 `MSPreds` 는 이미 `predictions.js` 가 덮어쓴 기록 모듈이므로, `drawCone()` 이 `MSPreds.seed(...)` 를 부르는 순간 예외가 나고 리포트는 통째로 에러 상태로 떨어진다. 종목·티어·캐시와 무관하게 **100% 재현**된다.

결과적으로 죽는 것:

- 기본분석 리포트(18a) — 앱의 본체
- 심화·전문 리포트(18b·18c) — 리포트를 못 지나가므로 도달 불가
- 해제 동선·예측 기록 생성 — 리포트가 만드는 것이라 매일 루프 전체가 시작되지 않는다

### 왜 관문 1505건이 초록이었나

모바일 테스트는 각 모듈을 Node 에서 `require()` 한다 — 모듈마다 **독립된 객체**를 받으므로 브라우저 전역 하나를 두 파일이 다투는 이 사고를 **원리적으로 볼 수 없다**. `predictions.js` 가 들어온 커밋(`d62945e`, 8/17 13:50)과 APK 빌드(14:27) 사이에 이 구멍을 볼 관문이 없었다.

> 교훈: **부팅 연기 시험(`aa89801`)이 잡는 것은 "스크립트 태그 누락"이지 "전역 충돌"이 아니다.** 실제 브라우저에서 각 화면을 열어 콘솔 오류 0을 단언하는 관문이 없으면 이 계열은 계속 새 나간다.

## 3. 진단 — 무엇이 잘못된 개발 과정이었나

1. **시안의 목적을 화면 목록으로 바꿔 읽었다.** 개편의 목적은 "사용자가 자발적으로 광고를 보게 만드는 것"이고, 수단은 **세 티어의 격차를 눈으로 겪게 하는 것 + 결과를 다음날 닫아 재방문 고리를 만드는 것**이다. 그런데 구현은 화면을 하나씩 "재스킨"하는 태스크로 잘렸고, 그 결과 **광고 진입점 6곳 중 리포트 해제 CTA 가 `심화분석 보기` 라는 무광고 버튼으로 남았다.** 목적이 화면 밖으로 밀려났다.
2. **시각 언어를 정보 위계가 아니라 텍스트로 납작하게 옮겼다.** 시안은 큰 수치·상태 아이콘·색으로 말하는 진행 점·마무리 문장으로 "판단"을 전달한다. 앱은 같은 정보를 균일한 행으로 늘어놓아 **무엇이 중요한지 화면이 말하지 않는다.**
3. **구조를 건드리지 않았다.** 하단 탭바(목록·분석·스쿱)가 없어 앱의 뼈대가 개편 이전 그대로다. 그래서 만든 화면들이 갈 곳이 없었고, 마지막 커밋은 지갑에 `더 보기` 라는 임시 통로를 뚫어 때웠다 — 시안에 없는 화면이다.
4. **검증이 코드 안에서만 돌았다.** 1505건은 모듈 계약을 지켰지만 **브라우저에서 화면을 여는 관문이 하나도 없었다.** 그래서 앱의 본체가 죽은 채 "관문 통과"로 배포·빌드까지 갔다.

## 4. 재시작이 지켜야 할 최소 규율 (다음 단계 입력)

- **동선 축으로 자른다** — 기술 축(타이포·시트·차트)으로 자르면 시안의 구조가 어느 태스크 담당도 아닌 채 남는다. 이번 실패의 재현이다.
- **모든 화면은 실제 브라우저에서 열려 콘솔 오류 0 + 시안 대조 스크린샷**으로 닫는다. 모듈 단위 테스트는 이 관문을 대신하지 못한다.
- **전역 이름은 단일 출처 표로 관리**한다(`MSPreds` 충돌 재발 방지).
- **광고 진입점은 화면의 CTA 로 존재**해야 한다 — 조건부 부록이 아니라.
