# 시안 전수 대조 — 목업 24장 vs 현 구현 (2026-08-11)

핸드오프 번들(`design_handoff/`)의 목업 보드 24장을 현 구현과 전부 대조한 결과다. **차이 목록이지 착수 결정이 아니다** — 무엇을 맞출지는 이 문서를 보고 정한다.

- 권위 출처: `design_handoff/MoneyScoop Mobile.dc.html` 의 **11a 「확정 사양과 화면 흐름」**. 턴 1~10에서 고른 것만 모은 최종안이다.
- 대조 대상: `mobile/www/` 전체(Phase 5 완료 시점, 커밋 `e5a1f63`)
- 보드 24장 = 턴 12개 × 옵션. 1b·1c는 **채택되지 않은 대안**(1a·2a가 채택)이라 차이 목록에서 제외했다.

## 2. 구조 차이 — 큰 것부터

### 2.1 재화(Scoops) 체계 전체가 없다 — 가장 큰 공백

11a 확정 사양이 못 박은 것:

| 항목 | 시안 |
|---|---|
| 재화 | Scoops · **시작 5개** · **보유 한도 20** · 1회 실행마다 차감, 결과는 영구 보관 |
| 분석 단계 | Basic 무료(5지표·일봉) / **Full 3스쿱**(32지표·일주월) / **Custom 5스쿱**(32+내 가중치) |
| 광고 | Quick 15초 **+1** / Full 30초 **+3** · 하루 8회 한도 · 재시청 2분 쿨다운 |
| 출석 | 매일 1회 +1 · 7일 연속 +5 상자 |
| 로그인 | 익명 시작 · **잔량이 5를 넘는 순간** 구글 연결 유도 |

이것이 없으면 온보딩 3화면(스쿱 5개 지급)·단계 선택·광고 게이트·결과 화면이 전부 성립하지 않는다. **화면 5개가 이 하나에 묶여 있다.**

시안이 명시한 설계 의도도 기록해 둔다 — *"24시간 전면 해금은 폐기 — 대신 1회 실행 = 재화 소모이고 결과는 히스토리에 영구 보관. 광고를 '당해서' 보는 게 아니라 모으려고 보게 만드는 구조."*

### 2.2 온보딩 5화면 — 설치 직후 여정이 통째로 없다

| 화면 | 시안 내용 |
|---|---|
| 1/5 콜드 오픈 | *"Where does this chart go next?"* + 32지표 설명 + `Show me how` |
| 2/5 원리 | *"32 opinions, one number."* + 17 up/6 flat/9 down 시연 + Bullish 68% |
| 3/5 왜 무료인가 | *"Ads pay for the engine. You decide when."* + **스쿱 5개 지급** + Earn/Spend 표 |
| 4/5 첫 종목 | *"What do you watch?"* + 검색 + 지역 칩(US/KR/JP/ETF) + Most watched today 6종 + `Continue with 3` |
| 5/5 동의·고지 | 맞춤 광고 토글 · 크래시 리포트 토글 · **Risk notice 전문** · 약관 동의 → `Open NVDA` |

현재는 앱을 켜면 시드 3종목(AAPL/NVDA/MSFT)이 이미 박힌 워치리스트가 뜬다. 시안은 **사용자가 직접 고르게** 한다(`MSStore.seedIfEmpty()`가 그 자리를 임시로 메우고 있다).

### 2.3 리포트 — 지평 4카드가 없다

2a·1a 모두 판정 아래에 **지평별 목표 카드 4장**을 둔다:

```
Tomorrow 164.90 +1.7%   In 1 week 168.20 +3.7%
In 1 month 170.70 +5.2%  In 3 months 178.40 +10.0%
```

현 구현에는 이 블록이 아예 없다. 예측 경로는 차트 콘에만 있고 숫자로 읽히지 않는다. **엔진은 이미 `prediction.path`를 갖고 있으므로 데이터가 아니라 표현의 공백이다.**

2a는 추가로 `Composite 170.7` · `Range 142.8–187.4` · `Horizon 80% cone`을 판정 옆에 둔다.

### 2.4 `Not checked at this level` — 능력 4줄 vs 지표 칩 27개

Phase 3부터 기록돼 온 차이. 6a 원문:

```
Not checked at this level
· Historical hit rate of this setup
· Indicators that disagree
· Weekly and monthly agreement
· Why each reading came out that way

"A Basic read tells you what five indicators say. It does not tell you whether that has ever worked."
```

**시안은 "무슨 지표가 빠졌나"가 아니라 "무슨 능력이 없나"를 말한다.** 그래야 다음 단계(Full)를 살 이유가 생긴다. 현 구현의 27칩은 정보량 결핍을 보여주지만 검증 결핍을 못 보여준다 — 4a가 말한 `The missing 27 can move this by ±14 points` 같은 임팩트 문장도 없다.

이건 티어 사다리(2.1)와 한 몸이라 따로 고치기 어렵다.

### 2.5 워치리스트에 빠진 것

1a 기준으로 없는 것:

- **검색창** (`Search ticker or company`)
- **필터 칩** (`All 8` / `US Tech` / `Semis` / `KR`)
- **우상단 스쿱 필 상시 노출** — 11a가 워치리스트 설명에 직접 적은 항목
- `{{ quotaLine }}` — 남은 일일 시청 한도 안내 줄

### 2.6 판정 옆 정직 장치가 없다 (8a·8b)

8b는 판정 **바로 아래**에 적중/오답 바를 요구한다:

```
58.1% right · 41.9% wrong
"Four calls in ten that looked like this one did not work out.
 Size your position for that, not for the 68%."
```

그리고 `What would change this call`(반증 조건 3개), `모를 때는 판정 거부 + 스쿱 미차감`. 전부 미구현.

8a의 **Misses를 기본 탭으로 두는 오답 공개**(13,197건 사후분석)도 없다.

> 이 수치들은 저장소의 실제 백테스트(`forge-backtest-report.json`, 86 시리즈 · 31,496 예측)에서 온 것이라 **지어낸 값이 아니다.** 붙일 때 원본을 그대로 쓸 수 있다.

### 2.7 숫자 역추적이 없다 (10b)

*"Every figure in a MoneyScoop report opens like this."* — 숫자를 누르면 `Reading / Crossover / Trend strength / Bias ±1 / × your weight` 계산 과정이 열린다. 10a가 내건 포지션(*"모든 숫자는 차트로 역추적"*)의 실행 장치인데 없다.

### 2.8 태블릿 3단 (1d 후반부)

1d는 폴드 2단과 **태블릿 3단(905dp+: 종목 / 리포트 / 지표 레일)** 을 같이 그린다. Phase 5는 2단만 했다. 지표 레일 칸은 `Indicators 12/32` + Lv1·Lv2 체크 목록 + `Apply` — PC 스쿱포지 3패널과 같은 구조다.

## 3. 비주얼 차이

2a가 디테일 지침을 직접 적어 뒀고, 대부분은 이미 지켜지고 있다.

| 지침 | 상태 |
|---|---|
| 카드 테두리를 헤어라인으로 낮춘다 | ✅ `--hairline` 사용 중 |
| 숫자는 전부 `tabular-nums` | ✅ `body`에 전역 적용 |
| 큰 수치는 자간을 조인다 | ✅ `.rp-verdict` `-.025em` |
| 섹션 라벨 10.5px · 자간 .14em | ⚠️ `.overline`만 그렇고 `.rp-sec-title`은 12px/.02em |
| 우측 가격축(눈금 + 현재가 태그) | ✅ `drawAxes` |
| 예측 시작선 | ✅ 점선 |
| 오실레이터 30/70·0선 값 라벨 | ✅ `draw-panels.js` |
| **하단 날짜축** | ⚠️ **눈금이 1개뿐** — 마지막 봉 날짜만 좌하단에 찍는다. 시안은 축 |
| 골드는 화면당 한 번만(제일 중요한 것에) | ⚠️ 검증 필요 — CSS에선 `.btn-primary`·선택 하이라이트뿐이지만 캔버스에서 현재가 태그·콘 채움·p1 선·진앙에 함께 쓴다 |
| 톤 체계 스틸=Basic | ✅ `.rp-tier`가 `--steel` |
| 톤 체계 골드=엔진이 말한 것 | ✅ 예측선 p1이 골드 |
| 톤 체계 플래티넘=내가 설정한 것 | — `--platinum` 토큰만 있고 미사용 (Custom 미구현이라 정상) |

**색·타이포 계보는 어긋나지 않았다.** 목업이 직접 적어 뒀다 — *"색·타이포·'항목 좌측 컬러 라인 금지' 규칙은 스쿱포지에서 그대로 가져왔습니다."* 현 `style.css`가 그 계보를 따르고 있다.

## 4. 카피 차이

Phase 3이 리포트·워치리스트를 시안 영문으로 맞춰 둬서 **핵심 라벨은 이미 정확하다**: `What was read` · `Not checked at this level` · `Likely somewhere in` · `BASIC` 모두 시안 원문 그대로다.

남은 것 하나가 중요하다.

### `Likely somewhere in` 이 다른 수치에 붙어 있다

| | 시안 (6a) | 현 구현 |
|---|---|---|
| `Likely somewhere in` | **확신 구간** `55–67%` — *"this is a rough read"* | **가격 범위** `142.80–187.40 · 23 bars` |
| 가격 범위 | 2a에서 `Range 142.8 – 187.4` + `Horizon 80% cone` 으로 **따로** 표기 | (위와 합쳐짐) |
| 1개월 목표 | `1-month target ≈ 170` 별도 줄 | 없음 |

같은 문구를 다른 양에 붙였다. 시안은 **확신에 오차를 붙이는 것**(68%가 아니라 55~67%)이 핵심인데, 현 구현은 그 장치가 없고 문구만 가격 범위로 갔다.

## 5. 의도적 이탈 — 되돌릴지 판단 필요

시안과 다르지만 **이유가 있어 그렇게 한 것들.** 지금 시점에 재검토할 값어치가 있다.

| 항목 | 시안 | 현 구현 | 당시 근거 |
|---|---|---|---|
| 워치리스트 확신 표기 | `68%` 퍼센트 | `4/5 agree` | Phase 1 — Basic 4지표라 값이 0/25/50/75/100뿐이라 퍼센트가 확률처럼 오독됨 |
| 시드 종목 | 온보딩에서 사용자가 3개 선택 | AAPL·NVDA·MSFT 자동 주입 | 온보딩 미구현의 임시 대체 |
| 폴드 목록 칸 | (시안 1d와 동일 결론) | 스파크라인·확신 숨김 | Phase 5 A′ — **시안과 독립적으로 같은 결론에 도달** |

세 번째는 차이가 아니라 **일치 확인**이다. 1d의 왼쪽 칸은 `NVDA / 162.20 / +2.41%` 뿐이고 스파크라인·확신이 없다 — A′가 실측 폭 예산만으로 도달한 결론과 같다.

## 6. 착수 순서 권고

의존 관계가 순서를 거의 결정한다.

1. **재화(Scoops) 체계** — 화면 5개가 여기 묶여 있다. 이것 없이는 4·5·6·7번 화면을 만들 수 없다. `SPEC-economy.md`(5KB)가 규칙을 따로 정해 뒀으니 그것부터 읽을 것
2. **온보딩 5화면** — 재화가 있어야 3/5(스쿱 5개 지급)가 성립한다. 다만 1·2·4·5화면은 재화와 독립이라 **부분 선행 가능**
3. **단계 선택 + 광고 게이트** — 1이 끝나면 바로
4. **리포트 보강**(지평 4카드 · 확신 구간 · 적중/오답 바) — 재화와 무관해 **언제든 가능**. 엔진이 이미 데이터를 갖고 있어 비용이 가장 싸다
5. **결과·Full / Custom** — 재화 + 티어 실행 경로가 선행
6. **정직 장치**(Misses 탭 · 방법론 · 판정 거부) · **숫자 역추적** · **계정** · **언어 설정**
7. **태블릿 3단** — 실측 기기가 없어 근거 없음. 보류

**4번이 지금 당장 착수 가능하고 체감 효과가 가장 큰 항목이다** — 재화 체계를 기다리지 않고 리포트 화면 하나를 시안 수준으로 끌어올린다.

## 7. 대조에서 제외한 것

- **1b·1c** — 채택되지 않은 대안(판정 우선 / 콘 주인공). 11a가 1a·2a를 골랐다
- **4a의 Core/Full/Tuned 명칭** — 5a에서 **Basic/Full/Custom** 으로 정리됐고 현 구현이 그쪽을 따르고 있다 ✅
- **7b의 자기비하 톤** — 10b 해설이 "설계 선택"으로 다시 썼다고 명시. 최종은 8a·10a 톤
