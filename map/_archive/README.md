# ⛔ 봉쇄 구역 — 읽지도 복사하지도 않는다

**2026-08-19 사용자 지시로 봉쇄.** 이 폴더 아래의 모든 것은 **폐기 자산**이며,
2차 시안 이후의 작업에서 **참조 대상이 아니다.**

```
_archive/mobile-2026-08-19/
├── www/ android/ test/ tools/      ← 중단된 앱 구현 (2026-08-19 개발 중단, 커밋 0c5bd0e)
├── sync-engine.mjs · package.json  ← vendor 동기화 · 의존성
└── docs/
    ├── design_handoff/             ← 1차 시안 (화면별 HTML · 동선 · 여정)
    ├── DESIGN-BRIEF*.md            ← 1차·2차 시안용 기능 분해도
    ├── DESIGN-INVENTORY.md · design-audit.md
    └── rebuild/ · BACKLOG-mobile.md ← 중단 시점 이력
```

## 왜 통째로 묶었나

**1차 시안과 그 시안으로 지은 구현을 따로 두면, 둘 중 하나는 반드시 참조된다.**
2차 시안이 나오면 거기에만 온전히 집중해야 하고, 개발부터 배포까지 새 트랙으로 완결되어야 한다.
그러려면 옛 트랙 전체가 한 덩어리로 닫혀 있어야 한다.

근거는 실패 사례다 — P1a·P1b 는 태스크 브리프가 *"기존 `build*` 패턴을 그대로 따르라"* 고 지시해
**개편 대상이던 옛 디자인을 구조적으로 보존**했다. 프로젝트 이름이 "앱 개편"인데 결과물은 개편 전의 연장이 됐다.
**참조할 수 있는 옛 것이 손에 닿는 곳에 있다는 사실 자체가 위험**이고, "조금만 참고하자"가 곧 오염이다.

그리고 1차 시안은 기준으로서도 이미 무효다. 그 시안대로 지은 것은 온보딩 7단계뿐이고,
리포트 화면군은 시안을 아예 보지 않고 정보 설계서만 보고 지어졌다.

그 코드는 *"별도로 만든다"* 는 폐기된 전제 위에 서 있다.
